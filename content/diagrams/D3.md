# D3 — how threat hunting fits together

Domain 3 is about **hunting**: you go looking for an attacker that no alert has caught yet. The objective pages teach each tool on its own. These seven pictures show how the tools join up, which data each one can reach, and which look-alikes the exam will try to swap. Read them after a few objective pages, then come back before the exam.

Dashed, muted boxes are **forward-links**: a construct from Domain 1 or Domain 2 that sits next to a D3 thing. They are pointers only. The detail lives in that domain.

## 1 · The hunting loop — from a guess to an incident

Every hunt follows the same loop. Start from a **hypothesis** about attacker behaviour. Run it in the tool that can reach the data. Keep what you find as evidence. If the query proved useful, **promote** it to a rule so it runs without you. The commonest trap sits in row 3: ==!advanced hunting has no bookmarks==. In the Defender XDR world the evidence step is **Link to incident**.

Objectives summarised: [D3.2.1](../objective/D3.2.1.html) · [D3.1.3](../objective/D3.1.3.html) · [D3.1.4](../objective/D3.1.4.html) · [D3.2.2](../objective/D3.2.2.html). [D3.2.1](../objective/D3.2.1.html) has its own Sentinel-only lifecycle diagram; this one adds the Defender side.

## 2 · Where the data lives — and which tool can reach it

Three stores sit at the bottom. Each tool above can only see the store in its own column. Advanced hunting spans two columns. It reads Defender XDR tables (30 days) **and** connected Sentinel tables (the workspace's analytics retention). ==!It does not read data kept only in the lake.== For long history you need the right-hand column. This is why "hunt over two years of sign-ins" never answers "advanced hunting".

## 3 · The table picker — ask the right cabinet

Before you write a single `where`, name the table. First ask **who recorded it**. A Defender sensor writes a Defender XDR table, filtered on `Timestamp`. A Sentinel connector writes a workspace table, filtered on `TimeGenerated`. Then match the question to the table. The red box lists the cabinets people open by mistake. ==!Zero rows from the wrong table looks exactly like "no problem".==
