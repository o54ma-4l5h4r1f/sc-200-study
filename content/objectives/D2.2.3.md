## Azure first

- An **entity** is any "thing" an alert mentions: a file, a user account, an IP address, a URL or domain, a device, a mailbox. In the Defender portal every entity name is a link to its own **entity page**.
- **Evidence** is the list of entities an incident or alert collected. In the new **incident cases** experience (preview, now Microsoft's recommended view) they sit under **Artifacts** > **Evidence**. The legacy incident page calls the same list the **Evidence and Response** tab. Each item shows a verdict and remediation status.
- A **file hash** (SHA1 / SHA256 / MD5) is the file's fingerprint. Two copies of the same malware have the same hash even if renamed. Indicators and file pages work on hashes.
- A **PE file** (portable executable) is a Windows program file: `.exe`, `.dll`, `.sys`. Several file actions work on PE files only.
- **Defender Antivirus cloud-delivered protection** and **sample submission** are Defender Antivirus settings. Blocking files, downloading quarantined copies and deep analysis lean on them.

New to these? Read the Foundations pages linked above.

## In one sentence

Entity investigation means opening the **file, user, IP address or URL/domain page** for an entity named in an alert, answering "how widespread is this and is it bad?", and then acting on files from the file page — **stop and quarantine**, **add an indicator**, **download or collect**, or **submit for deep analysis**.

## Why it exists

An alert says "`invoice.exe` ran on LAPTOP-07 and talked to 203.0.113.9". That is one sighting. The next question is "where else?" — other laptops, other logons, other machines talking to that IP.

Entity pages are **index cards**: one per suspect, listing every sighting across the organisation. Hop file → device → user → IP until you know the blast radius. Then act once, at the right scope.

Every entity page answers the same two questions — **is it bad** (verdicts, alerts) and **how far did it spread** (prevalence, devices) — and links back to device pages. Only the **file page** carries containment actions.

## What actually matters

**1. The file page.** Open it from search (choose **File**), the alert process tree, the incident graph, the artifact timeline or the device timeline. Sections:

| Section | What you learn |
|---|---|
| Overview / file details | Hashes, PE metadata, **VirusTotal detection ratio**, **Microsoft Defender AV detection**, first and last seen in the org, devices seen on in the last **30 days**, prevalence **outside** your org |
| Incidents and alerts | Every incident/alert involving the file |
| Observed in organization | **Devices** (file history up to **six months**) and **Cloud apps** (up to **30 days**, needs Defender for Cloud Apps) |
| File names | Every name the file used in your org (renamed malware shows up here) |
| File content and capabilities | For files Microsoft analysed: process/file/registry/network activity, strings, imports — and capabilities **mapped to MITRE ATT&CK** |

Prevalence numbers respect your **RBAC scope**. Two analysts with different device-group access can see different counts. Training unit 2 still shows the older layout (Alerts / Observed in organization capped at **100 devices** / Deep analysis / File names). The product docs describe the newer layout; the UI wins.

**2. File actions — the bar on top of the file page.** **Stop and quarantine file**, **Manage indicator**, **Download file** (or **Collect file**), **Ask Defender Experts**, **Manual actions**, **Go hunt**, **Deep analysis**.

**3. Stop and quarantine file.** Kills the running processes, quarantines the file **and deletes persistent data such as registry keys**, on every device where the file was seen in the **last 30 days**.

- Needs Windows 10 1703+, Windows 11 or Windows Server 2012 R2+ (training unit 2 omits servers; the product article wins).
- Defender Antivirus must run at least in **passive** mode.
- Not allowed on **Microsoft-signed** or trusted third-party-publisher files.
- Maximum **1,000 devices**. Action times out after **3 days** for offline devices.
- For more devices, or to keep blocking after the action, ==+add a block indicator==.
- A warning appears for widely used files. The user sees a notification. Each device's timeline gets an event.
- To restore on a device (elevated prompt): `MpCmdRun.exe -Restore -Name EUS:Win32/CustomEnterpriseBlock -All`. It restores every custom-blocked file quarantined on that device in the last **30 days**. Run it on each device.

**4. Add indicator (block or allow a file).** An **indicator** is a hash rule that applies to every device: **Allow**, or **Block and raise an alert**. Facts:

- First turn on **Allow or block file** in **Settings** > **Endpoints** > **General** > **Advanced features**, then **Save preferences**.
- Needs Defender Antivirus with **cloud-delivered protection**, client 4.18.1901+, Windows 10 1703+.
- Works on **PE files**, and the file must already appear in a device timeline.
- A couple of minutes of latency.
- Files blocked by an indicator do **not** appear in the file's Action center. The **alerts** still show in the alerts queue.
- Remove with **Edit indicator**, or in **Settings** > **Endpoints** > **Rules** > **Indicators** (listed by hash).

**5. Download file vs Collect file.**

| | Download file | Collect file |
|---|---|---|
| Source | Copy Microsoft already holds (for example the cloud backup made at quarantine) | The file at its **current path on the device** |
| Output | Password-protected `.zip`, you set the password | Same |
| Shows when | Defender for Endpoint already stores the file | It doesn't — the button changes to Collect file |
| Limits | Quarantine backup max **100 MiB**; needs **sample submission** on; **Download quarantined files** setting (on by default) | Disabled if the file wasn't seen in the org in the last **30 days** |

Permission: PE files need **Security Administrator**, **Advanced live response** or **Alerts**. Non-PE files (`.txt`, `.docx`) need **Security Administrator** or **Advanced live response**. In unified RBAC: ==@File collection (manage)== ("collect or download relevant files for analysis"). Since **16 February 2025**, new Defender for Endpoint customers get unified RBAC only; existing customers keep their old roles.

| Legacy MDE permission | PE files | Non-PE files |
|---|---|---|
| View data | No | No |
| Alerts investigation | Yes | No |
| Live response basic | No | No |
| Live response advanced | Yes | Yes |

**6. Deep analysis.** Runs the file in a Microsoft **cloud sandbox** and returns a report with **Behaviors** and **Observables** (contacted IPs, dropped files, registry changes). Results are matched against threat intelligence and can raise alerts. Facts: a **Plan 2** capability (the service description lists "sandbox (deep analysis)" under P2). **PE files only** (not Windows Store apps). Submit is enabled when the sample is in Microsoft's backend or was seen on Windows 10/11/Server 2012 R2+. Sample collection times out after **3 hours**. Up to **10 minutes** latency before the button appears. If the file was never on such a device, submit it through the **Microsoft Security Intelligence submission portal** first.

**7. The user page.** Reach it from the dashboard, alerts queue or device page, or search (**User**). Shows: related open incidents, active alerts, **SAM name**, **SID**, **Microsoft Defender for Identity alerts** (needs the MDI integration switched on in Advanced features), devices logged on to, **logon types**, first and last seen, role. Tabs: **Overview**, **Alerts**, **Observed in organization** (devices the account logged on to, with the most and least frequent users). Search filters: 1 day, 3 days, 7 days, 30 days, 6 months. Linux logons are not shown. With Defender for Identity or Entra ID integration, training unit 3 adds sign-in risk, MFA registration and AD group memberships. Use it for **lateral movement**: which other machines did this account touch?

**8. The IP page.** Geolocation (ISP/organization, **ASN**, country, city, carrier, coordinates), **Related alerts**, **IP activity observed in the organization** (devices that connected, list capped at **100**), **Prevalence** (default **30 days**, first and last seen). Training unit 4 also lists **reverse DNS names**. Search returns only IPs that your devices actually communicated with.

**9. The URL / domain page.** Domain details and **whois** registrant info, the **Microsoft verdict** (from Microsoft threat intelligence), incidents and alerts (bar chart over **180 days**), prevalence over **30 days**, then tabs:

- **Devices** — range from 1 day to six months; **Export** to CSV.
- **Emails** — messages containing the URL, last 30 days.
- **Clicks** — user clicks, last 30 days.

The **domain** page aggregates every URL under the same FQDN. `sub.domain.tld/path1` and `sub.domain.tld/path2` roll up, but `othersub.domain.tld` is a different domain page. Disagree with the verdict? **Submit to Microsoft for analysis** as *clean*, *phishing* or *malicious*.

## Where it lives

All in the **Microsoft Defender portal** (`security.microsoft.com`).

| Task | Path |
|---|---|
| Find an entity | Top search box > choose **File**, **User**, **URL** or **Device**, or paste an IP |
| From an incident (incident cases) | **Cases** > **Incident** > case > **Artifacts** > **Evidence** (or **Artifacts** > **Assets** for devices and users), or select the entity in **Overview** > **Attack graph** |
| From an incident (legacy page) | incident > **Evidence and Response** tab, or the entity in the attack story graph |
| Turn on file blocking | **Settings** > **Endpoints** > **General** > **Advanced features** > **Allow or block file** |
| Quarantined-file download | **Settings** > **Endpoints** > **General** > **Advanced features** > **Download quarantined files** |
| Manage indicators | **Settings** > **Endpoints** > **Rules** > **Indicators** |
| Track file actions | **Action center** (submission time, Success / Failed / Pending device counts) |

Restore a quarantined file on one device (elevated Command Prompt, from the Defender platform folder):

```console
MpCmdRun.exe -Restore -Name EUS:Win32/CustomEnterpriseBlock -All
```

## Exam traps

- ==!Stop and quarantine scales to the whole estate.== ==+It is capped at 1,000 devices and 30 days of sightings; use a block indicator for broad, lasting blocking.==
- ==!An indicator removes the file that's already there.== ==+An indicator blocks future reads/writes/execution and can alert==; stop and quarantine cleans current copies.
- ==!You can block any file type with an indicator.== The response-action version supports **PE files** (`.exe`, `.dll`).
- ==!Stop and quarantine works on Microsoft-signed files.== It does not.
- ==!Deep analysis runs on the user's device.== ==+It runs in a Microsoft cloud sandbox.== PE files only.
- ==!Download file pulls the file off the device.== ==+Download uses the copy Microsoft holds; Collect file fetches it from the device path.==
- ==!The IP page shows every IP on the internet.== Search returns only IPs your devices talked to. URL search works the same way.
- ==!Deep analysis is in every Defender for Endpoint plan.== ==+It is a Plan 2 (sandbox) capability.==
- ==!A domain page includes all its subdomains.== Each FQDN has its own page.
- "Investigator can download `.exe` files but not `.docx`" → they have **Alerts** but not **Advanced live response** / Security Administrator.
- Stop and quarantine also **deletes persistence such as registry keys**. Look for that phrase in answer options.

## Skip

- **Skip:** the deep-analysis troubleshooting steps (`AllowSampleCollection` registry value, OU changes). Know only "PE only, sandbox, Behaviors + Observables".
- **Skip:** the full quarantined-file download requirement list (engine 1.1.17300.4, etc.). Know: Defender AV active, cloud protection on, sample submission on.
- **Skip:** the long batch one-liner that changes into the Defender platform folder before `MpCmdRun`. Know the `-Restore -Name EUS:Win32/CustomEnterpriseBlock -All` part.
- **Skip:** the IP page's latitude/longitude/postal code fields one by one. Know geo + ASN + devices + prevalence.
- **Skip:** *Ask Defender Experts* and *Manual actions*. Paid service / Plan 1 detail, not investigation skills.
