## Azure first

- A **Log Analytics workspace** is the log database Microsoft Sentinel reads. Every connector on this page ends by writing rows into one of its **tables** (`SecurityEvent`, `Syslog`, `OfficeActivity`…).
- **Microsoft Sentinel** is the SIEM (the search-and-alert layer) switched on over that workspace. Today you use it inside the **Microsoft Defender portal** (`security.microsoft.com`); the Azure portal version is unsupported after **31 March 2027**.
- The **Azure Monitor Agent (AMA)** is the program on a Windows or Linux machine that ships its logs. A **data collection rule (DCR)** is the Azure object that tells the agent what to ship.
- **Azure Arc** gives a non-Azure server (on-premises, another cloud) an Azure identity, so AMA can be installed on it.

New to these? Read the Foundations pages linked above.

## In one sentence

A **data connector** is the ready-made "plug" in Microsoft Sentinel that brings one kind of log into the workspace — and choosing one means answering *where does the data come from, how can it travel, and which table must it land in*.

## Why it exists

Think of a building's CCTV room. Cameras from different makers need different cables and adaptors before their pictures reach the screens. A connector is the adaptor. Microsoft has written hundreds of them, so you do not wire each source yourself.

The exam does not ask you to memorise hundreds. It asks you to **pick the right one for a scenario**: "on-premises domain controllers, you need the Security log and the built-in Windows rules must work" — which connector? That is the skill.

## What actually matters

**1. Connectors come from the Content hub, inside solutions.** A **solution** is a package from Microsoft or a partner: data connectors plus analytics rules, workbooks, hunting queries, parsers and playbooks. The **Data connectors** page lists only connectors whose solution is ==@installed==. Can't find a connector? Install its solution first. Installing needs **Microsoft Sentinel Contributor** at resource-group level; configuring a connector needs read and write on the workspace. A connector can be disconnected but not deleted.

**2. Connection types.** Microsoft groups the Microsoft-service connectors into three types:

| Type | How data moves | Examples |
|---|---|---|
| API-based (service-to-service) | Microsoft cloud pushes it; you tick boxes | Microsoft Entra ID, Microsoft 365, Defender XDR, Defender for Cloud |
| Diagnostic settings (some managed by **Azure Policy**) | An Azure resource's own export setting | Azure Activity, Key Vault, Azure Firewall |
| Agent-based | AMA on the machine, rules in a DCR | Windows Security Events, Windows DNS, Syslog, CEF |

Non-Microsoft devices mostly use **CEF via AMA** or **Syslog via AMA** as a base (D1.3.4). Each connector page shows a **Data types** list — the exact table it writes. Check it.

**3. The Windows choice — the heart of this bullet.**

| Connector | Agent | Where events come from | Table |
|---|---|---|---|
| ==+Windows Security Events via AMA== | AMA on **each** server | Security log + AppLocker; sets All / Common / Minimal / Custom | `SecurityEvent` |
| Windows Forwarded Events | AMA on **one WEC server** | Events forwarded by Windows Event Forwarding | `WindowsEvent` |
| ==!Security Events via Legacy Agent== | Log Analytics agent (MMA) | Same sets, no Custom/XPath | `SecurityEvent` |
| (Azure Monitor DCR, not a Sentinel connector) | AMA | Any Windows log you pick | `Event` |
| Windows DNS Events via AMA | AMA on DNS servers | DNS server logs | `ASimDnsActivityLogs` |
| Windows Firewall Events via AMA | AMA | Windows Firewall logs | (DCE required) |

Microsoft recommends **Windows Security Events via AMA**. The legacy connector uses the Log Analytics agent, which was ==!deprecated on 31 August 2024==; use it only where AMA isn't supported. Non-Azure machines need **Azure Arc** for any AMA connector.

**4. The table trap.** Forwarded events — even Security-log events — go to `WindowsEvent`, ==!not== `SecurityEvent`. Many built-in Windows rules query `SecurityEvent`. If you need them unchanged, use Windows Security Events via AMA, or rewrite the rules (or use ASIM parsers — normalising functions that read both tables). And the reverse trap: picking the Security log in a *plain* Azure Monitor DCR sends it to `Event`, which Sentinel's Windows content does not read.

**5. Sysmon and other non-Security logs.** **Sysmon** (a free Microsoft tool that logs process creation and network connections) writes to `Microsoft-Windows-Sysmon/Operational`. The training collects it with the Windows Forwarded Events connector's DCR and the custom XPath `Microsoft-Windows-Sysmon/Operational!*`.

**6. Microsoft-service connectors you should recognise.**

| Connector | Writes to | Note |
|---|---|---|
| Microsoft 365 | `OfficeActivity` | Tick Exchange, SharePoint, Teams |
| Microsoft Entra ID | `SigninLogs`, `AADNonInteractiveUserSignInLogs`, `AADServicePrincipalSignInLogs`, `AADManagedIdentitySignInLogs`, `AADProvisioningLogs`, `ADFSSignInLogs`, `AuditLogs`, plus risk tables (`AADUserRiskEvents`, `AADRiskyUsers`…) | Each log type is a separate tick box |
| Microsoft Entra ID Protection | `SecurityAlert` | Alerts only; optional "create incidents" rule |
| Microsoft Defender for Cloud | `SecurityAlert` | Two versions: **Subscription-based (Legacy)** — a toggle and optional bi-directional sync per subscription; **Tenant-based (Preview)** — every subscription at once, recommended alongside Defender XDR |
| Microsoft Defender XDR | incidents, alerts, advanced-hunting events | **Automatic** once Sentinel is onboarded to the Defender portal |

The four product connectors (Defender for Endpoint, Identity, Office 365, Cloud Apps) are now **legacy**. When Sentinel is onboarded to the Defender portal (and you are licensed for Defender XDR), the Defender XDR connector is set up for you. The alert connectors it replaces — those four plus ==@Microsoft Entra ID Protection== — are disconnected. Defender XDR incidents and alerts (`SecurityIncident`, `SecurityAlert`) are ingested free; raw advanced-hunting tables (`DeviceFileEvents`, `EmailEvents`…) are billed.

**7. Custom routes and a retirement.** No connector? Use the **Logs Ingestion API**, the **Codeless Connector Framework (CCF)**, AMA custom logs, or Logstash. The old **HTTP Data Collector API** ==!stopped being supported after 14 September 2026== — the training still names it ("Log Analytics Data Collector API"). Ignore that.

## Where it lives

Both portals work until 31 March 2027; the Defender portal is the future.

| Task | Defender portal | Azure portal |
|---|---|---|
| Find / install a solution | **Microsoft Sentinel > Content management > Content hub** | **Microsoft Sentinel > Content management > Content hub** |
| Configure a connector | **Microsoft Sentinel > Configuration > Data connectors** > connector > **Open connector page** | **Microsoft Sentinel > Configuration > Data connectors** |
| See which machines report | **System > Settings > Microsoft Sentinel** > workspace > Log Analytics settings, then **Settings > Agents** | **Configuration > Settings > Workspace settings > Agents** (Windows / Linux tabs) |
| Query the data | **Investigation & response > Hunting > Advanced hunting** | **Logs** |

A solution can also be deployed as code: the wizard's **Download a template for automation** link gives an ARM template.

## Exam traps

- "Forward the Security log from 500 servers through a WEC server; built-in Windows rules must work unchanged." ==!Windows Forwarded Events== writes `WindowsEvent`, so the rules miss it. ==+Windows Security Events via AMA== writes `SecurityEvent`.
- "On-premises server, AMA connector won't list it." ==+Install Azure Arc first.== The machine must be Arc-enabled before you enable the connector.
- "Legacy agent is fine, it's still in the gallery." ==!Deprecated 31 August 2024.== Pick the AMA connector.
- "Data connector missing from the Data connectors page." ==+Install the solution from Content hub.== Not a permissions problem by default.
- "Collect only event IDs 4624 and 4625." Only AMA can filter with **Custom / XPath**. The legacy connector only offers the preset sets.
- Entra ID Protection writes to `SecurityAlert`, not `SigninLogs`. Microsoft 365 writes to `OfficeActivity`.
- "Need Defender XDR incidents in Sentinel in the Defender portal" — ==+nothing to configure==; it's automatic. In the Azure portal you enable the Defender XDR connector.
- A plain Azure Monitor DCR with the Security log → `Event`. ==!Not the Sentinel table.==
