## Azure first

- **Defender for Endpoint (MDE)** keeps a live connection from each onboarded device to the cloud. That connection is what lets you act on a laptop you never touch: isolate it, scan it, open a shell on it.
- The **device page** in the Defender portal (`security.microsoft.com`) carries a row of **response action** buttons across the top. Every action in this lesson starts there.
- **Permissions** come from either **Defender for Endpoint roles** (older model: *Active remediation actions*, *Live response capabilities*) or **Defender unified RBAC** (newer model: *Response*, *Basic live response*, *Advanced live response*). Device groups also limit *which* devices you can act on.
- The **Action center** is the portal's log of every action — who, when, success or failure.
- **Plan 1 vs Plan 2:** Plan 1 has only four manual actions. Everything else here needs **Defender for Endpoint Plan 2**.

New to these? Read the Foundations pages linked above.

## In one sentence

Device response actions are the buttons on a Defender for Endpoint device page that **contain** a compromised machine (isolate, restrict app execution, contain), **clean** it (antivirus scan), **collect evidence** from it (investigation package) or give you a **remote shell** on it (live response) — every one logged in the Action center.

## Why it exists

You found a burning machine in D2.2.1. Now you must stop the fire spreading *and* keep the evidence. Think of a hospital. **Isolation** is the quarantine ward: the patient stays monitored by doctors (Defender) but cannot meet visitors (the network). **Restrict app execution** is "no outside food — hospital meals only" (only Microsoft-signed programs run). The **investigation package** is a full set of blood tests taken in one go. **Live response** is the doctor walking into the room with instruments.

Without these, a SOC analyst would phone the user, ask them to pull the network cable and wait for a technician. Attackers move faster than that.

## What actually matters

**1. The action bar.** On a device page: **Manage tags**, **Initiate automated investigation**, **Initiate live response session**, **Collect investigation package**, **Run antivirus scan**, **Restrict app execution**, **Isolate device**, **Contain device**, **Consult a threat expert**, **Action center**. Every action asks for a **comment**. Devices onboarded as **high-value assets** (domain controllers, ADFS) can be onboarded in **Restricted** security-operations mode, which disallows chosen groups: **Basic response** (AV scan, collect file, investigation package), **Advanced response** (isolate, restrict app execution, request remediation), **Live response**, **Device protection** (AIR). The device shows a *Restricted security operations* tag. The tenant switch is **Settings** > **Endpoints** > **Advanced features** > **Allow restricted security operations during onboarding**. The choice is fixed at onboarding — changing it means offboard and re-onboard.

> **Current-state caveat:** since **1 September 2026**, automated investigation and response (AIR) no longer runs as a separate experience or manual trigger for Defender for Endpoint. Microsoft says to run a **full antivirus scan** for on-demand investigation instead. AIR remains for Defender for Office 365. Expect older questions to still show *Initiate automated investigation*.

**2. Isolate device — the most-tested action.**

- Cuts the device off the network but **keeps its connection to the Defender for Endpoint service**, so monitoring and live response still work.
- **Full** isolation, or **selective** isolation: you may allow **Outlook and Microsoft Teams** to keep working. Selective isolation can also use **isolation exclusions** (processes and destinations that stay reachable). The docs list selective isolation for Windows 10 1703+ in one place and 1709+ in another; the training unit says 1709 and adds Skype for Business. Know "Outlook and Teams".
- The user sees a "no network connection" notification (Windows only).
- **Lifted automatically after seven days.** Undo any time with **Release from isolation**.
- An offline device: MDE retries for up to **three days**, then you must reissue.
- Needs at least the **Active remediation actions** role and access to the device's **device group**.
- Gotchas: a full-tunnel VPN can stop the device reaching MDE once isolated (use split tunnelling). Isolating a Hyper-V host blocks all its child VMs. Linux isolation needs `iptables`/`ip6tables`, and an admin editing an iptables rule lifts it. Behind a **web proxy** (PAC, WPAD, static) a fully isolated device may never recover — use **selective** isolation there. macOS and Linux isolation support **no exclusions**.
- If an isolated device becomes unresponsive, the device page offers **Download script to force-release a device from isolation**. The script works for that device only and **expires in three days**.

**3. Restrict app execution.** Applies a **code integrity policy** so only files signed by a **Microsoft-issued certificate** can run. Stops the attacker launching new tools. Needs Windows 10 1709+ / Windows Server 2019+ and **Microsoft Defender Antivirus**. Reverse with **Remove app restrictions**. The user gets a notification.

**4. Contain device (different from isolate).** Used for an **unmanaged** or not-yet-onboarded device. It does not touch the bad device. Instead, **every onboarded device blocks traffic to and from it**. Microsoft recommends containing no more than **100 devices** at once. Changes reach onboarded devices within about **5 minutes**. Undo with **Release from containment**. *Contain IP* and *Contain user* are applied automatically by attack disruption — lesson D2.2.4. Know four facts now:

- **Automatic device isolation** (Preview, attack disruption) hits onboarded **workstations** only. Tag a device and exclude it with a *policy application*; the action then shows **Skipped** in the Action center.
- **Contain user** makes onboarded devices block that identity's incoming **network logons, RPC, SMB and RDP**. It ==!does not disable the account== in Entra ID or AD. It is **automatic only** (no manual button), lifts itself within **five days**, and **Undo** needs **Global Administrator**.
- **Contain critical assets** (domain controllers, DNS, DHCP servers tagged critical) blocks only specific ports and directions, so the server keeps running.

**5. Run antivirus scan.** Choose **Quick** or **Full**. Works even if Defender Antivirus is in **passive** mode next to another antivirus. CPU is capped by `ScanAvgCPULoadFactor` (default **50%**). Results: Action center, a timeline event, and Defender Antivirus alerts for anything found.

**6. Collect investigation package.** A zip snapshot of the device's current state, downloadable from the **Action center** (*Package collection package available*) or the device details. Collection can fail on **low battery** or a **metered connection**. Windows folders:

| Folder / file | What it shows |
|---|---|
| ==@Autoruns== | Auto-start registry keys (ASEPs) — **persistence** |
| Installed programs | CSV of installed software |
| Network connections | `ActiveNetConnections.txt`, `Arp.txt`, `DnsCache.txt`, `IpConfig.txt`, firewall logs — **C2 and lateral movement** |
| Prefetch files | Recently run programs, even deleted ones |
| Processes | CSV of running processes |
| Scheduled tasks | CSV of scheduled tasks |
| Security event log | The Windows Security log (open in Event Viewer) |
| Services | CSV of services and states |
| SMB sessions | `SMBInboundSessions`, `SMBOutboundSession` — exfiltration, lateral movement |
| System Information | `SystemInformation.txt` |
| Temp Directories | Files in `%Temp%` per user |
| Users and Groups | Group membership files |
| WdSupportLogs | `MpCmdRunLog.txt`, `MPSupportFiles.cab` |
| CollectionSummaryReport.xls | What was collected and any errors |

macOS and Linux packages hold similar categories (processes, network connections, users and groups, sign-in history). Linux also includes **Client Analyzer** diagnostics.

**7. Live response — prerequisites.**

- Turned on in **Settings** > **Endpoints** > **Advanced features** > **Live Response**. Only users with **Manage portal system settings** can switch it on.
- **Live Response for Servers** is a separate toggle (recommended).
- **Live Response unsigned script execution** is a third, optional toggle. Signature checks apply to PowerShell scripts only.
- Your role decides **basic** or **advanced** commands.
- Uploading to the **library** from the console needs **Manage security settings**. The **Library management** page does not.
- Devices onboarded in high-value-asset **restricted mode** never run live response scripts.

**8. Live response — basic vs advanced.** This split is the core exam fact.

| Basic (read-only investigation) | Advanced (changes things) |
|---|---|
| `cd`, `cls`, `connect`, `dir`, `help`, `jobs`, `status`, `trace` | `run` — run a PowerShell (or Bash) script **from the library** |
| `processes`, `services`, `drivers`, `connections`, `registry` | `putfile` — copy a library file to the device (deleted on restart by default) |
| `persistence`, `scheduledtasks`, `startupfolders` | `library` — list library files |
| `fileinfo`, `findfile` | `remediate` — delete a file, stop a process/service, remove a task or registry entry |
| `getfile PATH` — download a file; `fg COMMAND-ID` | `undo` — restore a remediated entity (Windows) |
| | `analyze` — verdict from incrimination engines (Windows) |
| | `collect`, `scan`, `isolate`, `release` — macOS/Linux versions of the buttons |

Note the trap: `getfile` is **basic**. `putfile` and `run` are **advanced**.

Useful syntax: `getfile PATH &` downloads in the **background**; `-auto` runs a prerequisite command for you (`remediate file PATH -auto`); `-output json` or `-output table`; `processes > output.txt` pipes to a file. **Ctrl+C** cancels in the portal only — the command may still finish on the device. The **Command log** tab records every command.

**9. Live response — limits (docs) and where the training disagrees.**

| Limit | Product docs (current) | Training unit 5 (older) |
|---|---|---|
| Concurrent sessions (tenant) | **50** | 10 |
| Inactive session timeout | **30 minutes** | 5 minutes |
| Sessions per user | **5** concurrent | 1 |
| Sessions per device | 1 | 1 |
| Command timeout | 10 min (30 min for `getfile`, `findfile`, `run`) | — |
| `getfile` | 3 GB | 3 GB |
| `fileinfo` | **30 GB** | 10 GB |
| `library` upload | 250 MB | 250 MB |
| `putfile` | 300 MB Windows, 10 MB other platforms | — |

The product docs win. Two more training-unit oddities: its *advanced* table lists `getfile` again (with `-auto`) even though its basic table already has it, and it says unified RBAC **Response (manage)** alone grants live response. The product docs and the RBAC mapping say **Basic/Advanced live response (manage)**. Go with the docs. The training unit also adds a prerequisite the console article doesn't list: the device's **device group must have an automation remediation level** (at least the minimum), or you cannot open a session. The live response **API** article states the same rule, so treat it as real.

**10. Permissions.**

| Task | Defender for Endpoint role permission | Unified RBAC permission |
|---|---|---|
| Isolate, restrict, contain | Active remediation actions | Security operations \ Security data \ **Response (manage)** |
| Run AV scan, collect investigation package, manage tags | Alerts investigation | Security data \ **Alerts (manage)** |
| Live response, read-only commands, download files | Live response capabilities – basic | **Basic live response (manage)** |
| Upload files, run scripts, remediate | Live response capabilities – advanced | **Advanced live response (manage)** + File collection |
| Turn on live response | Manage portal system settings | Authorization and settings \ **System settings** |
| Upload to the library from the live response console; force-release from isolation | Manage security settings in the Security Center | Authorization and settings \ Security settings \ **Core security settings (manage)** |

## Where it lives

All in the **Microsoft Defender portal** (`security.microsoft.com`).

| Task | Path |
|---|---|
| Any device action | **Assets** > **Devices** (older docs: **Endpoints** > **Device inventory**) > device > action bar (or **…** menu) |
| Turn on live response | **System** > **Settings** > **Endpoints** > **Advanced features** > **Live Response** / **Live Response for Servers** / **Live Response unsigned script execution** |
| Script library | **Settings** > **Endpoints** > **Library management** |
| Check status, download package | **Actions & submissions** > **Action center** (`security.microsoft.com/action-center`) — **Pending** and **History** tabs |
| Per-incident status | incident > **Activities** tab |

API equivalent of the console: `POST https://api.security.microsoft.com/API/machines/{machine_id}/runliveresponse`, permission `Machine.LiveResponse`, commands **PutFile**, **RunScript**, **GetFile** in that order. Actions started from the device page are not visible through the MachineActions API.

Live response examples:

```console
processes
getfile c:\Users\user\Desktop\work.txt -auto
analyze file c:\Users\user\Desktop\malware.txt
run script.ps1
remediate file c:\Users\user\Desktop\malware.exe -auto
```

## Exam traps

- ==!Isolation cuts the device off from Defender too.== ==+It keeps the MDE service connection==, so you can still run live response on an isolated device.
- ==!Contain device and isolate device are the same.== ==+Isolate acts on the onboarded device itself. Contain makes every *other* onboarded device block an unmanaged/compromised device.==
- ==!Restrict app execution blocks all apps.== ==+It allows Microsoft-signed files and blocks the rest.==
- ==!getfile is an advanced command.== ==+getfile is basic; putfile, run, remediate and undo are advanced.==
- ==!You can run any script from your PC in a live response session.== ==+Scripts must be uploaded to the library first==, and unsigned PowerShell needs the *unsigned script execution* setting.
- ==!Live response is on by default.== ==+It must be enabled in Advanced features==, servers separately.
- ==!Isolation is permanent until released.== It is **lifted automatically after seven days**.
- ==!A greyed-out Live response button means you lack the role.== It can also mean the device was onboarded in **Restricted** mode as a high-value asset.
- "Need the attacker's persistence and network state in one download, without a shell" → ==+Collect investigation package== (Autoruns, Network connections, Scheduled tasks…).
- "Defender AV is passive because another antivirus is installed — can I still scan?" → yes, the remote scan works in passive mode.
- ==!Contain user disables the account.== ==+It only makes onboarded devices refuse that identity's network logons (RPC, SMB, RDP)==; the Entra/AD account stays enabled. Undo needs Global Administrator.
- Plan 1 offers only: run AV scan, isolate device, stop and quarantine a file, add a file indicator. Live response and investigation package are **Plan 2**.

## Skip

- **Skip:** the exact Windows build and KB numbers for live response and WdSupportLogs. Know "Windows 10/11, Windows Server 2012 R2+ (2016/2012 R2 need the unified agent), macOS and Linux".
- **Skip:** the deep-analysis sample-collection registry key and the full Mac/Linux package table row by row. Know that macOS/Linux packages exist and hold the same kinds of data.
- **Skip:** *GPO hardening* and *Safeboot hardening* (predictive shielding, Preview). They are automatic, not analyst actions.
- **Skip:** *Consult a threat expert* beyond its name. It hands you to Microsoft's expert service (Endpoint Attack Notifications), which is a separate offering, not an analyst action.
- **Skip:** the *Analyze* button on **Library management** (Copilot script analysis). It needs a Security Copilot licence and is not on the blueprint.
- **Skip:** the `runliveresponse` API request and response bodies. Know the permission name `Machine.LiveResponse` at most.
- **Skip:** the live response Linux kernel flags (`CONFIG_NETFILTER` and friends). Know only that Linux isolation uses `iptables`.
