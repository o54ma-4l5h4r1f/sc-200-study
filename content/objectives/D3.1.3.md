## Azure first

- **The Defender portal** (`security.microsoft.com`) is Microsoft's single security website. **Advanced hunting** is its query page.
- It queries **Defender XDR data** (needs Defender for Endpoint / Office 365 / Identity / Cloud Apps licences) and, once a **Microsoft Sentinel workspace** is connected, your **Sentinel tables** too. Sentinel works in the Defender portal without an E5 licence.
- **Two permission worlds** apply. Entra roles (Security Reader, Security Administrator, Global Reader …) or Defender **unified RBAC** permissions open Defender data. The Azure role **Microsoft Sentinel Reader** (at least) opens Sentinel data here.
- An **incident** is a case file that groups related **alerts**. Advanced hunting can push your own query results into one.
- **Licence note:** with an Azure subscription only, you can run advanced hunting over Sentinel tables, save and share queries. **Guided mode** and **Take actions** work on Defender XDR data only — treat those parts as a portal tour.

New to these? Read the Foundations pages linked above.

## In one sentence

Advanced hunting is the Defender portal page where you build a query (by hand in KQL, or by clicking in the guided **query builder**), run it inside fixed limits, and then do something with the result — save or share it, link the rows to an incident, take a response action, or turn it into a custom detection.

## Why it exists

Writing a good query is only half the job. A hunter needs a workbench around it: a place to keep the queries that worked, borrow ones experts wrote, and act on what they find without copying device names into another tool.

Think of a library reading room. The editor is your desk. **My queries** is your own notebook. **Shared queries** is the team shelf. **Community queries** is the public shelf of expert-written books. **Link to incident** is filing your evidence into the case folder. **Take actions** is phoning security to lock a door. The room has opening hours and a borrowing limit — those are the **quotas**.

## What actually matters

### 1. Two modes: guided and advanced

| | **Guided mode** | **Advanced mode** |
|---|---|---|
| You build the query by… | dropdowns in the **query builder** | typing KQL in the **query editor** |
| Open it with | **Create new > Query in builder** | **Create new > Query** (a new tab) |
| KQL needed? | No | Yes |
| Data | ==!Defender XDR data only== | Defender XDR + connected Sentinel tables |
| Switch | **Edit in KQL** opens the generated KQL in a new advanced tab | — |

Guided mode pieces you should recognise by name:

- **Data domain** picks the scope: **All domains**, **Endpoints**, **Email and collaboration**, **Apps and identities**, **Cloud infrastructure**, **Exposure management**.
- **Basic filters** come first and are joined with **AND only**. Flip the **All filters** toggle for every filter and condition, then combine conditions with **AND** / **OR** and **Add subgroup**.
- **EventType** in guided mode is the same thing as the `ActionType` column in KQL.
- **Smart auto-complete** suggests device and user names as you type.
- **Load sample queries** fills the builder with a ready query (it replaces what you had).
- **Sample size** limits rows while you test. Docs say the default is **10,000**, "the maximum number of records that can be returned"; drop it to 10 or 100 while testing.

### 2. The advanced-mode editor

- **Create new** opens another tab inside the page — use these, not extra browser tabs (you can lose unsaved queries).
- **Several queries in one tab:** separate them with an empty line; the one under your **cursor** is the one that runs.
- **Time range** picker next to **Run query**. If your KQL has its own time filter, the picker shows **Set in query**. All data and all queries are **UTC**; results display in your chosen time zone.
- Left pane tabs: **Schema**, **Functions**, **Queries**, **Detection rules**, each with a **Favorites** section.
- **Getting started** offers sample queries to run.

```kql
// Defender — the training module's first hunt: PowerShell download cradles in the last 7 days
union DeviceProcessEvents, DeviceNetworkEvents
| where Timestamp > ago(7d)
| where FileName in~ ("powershell.exe", "powershell_ise.exe")
| where ProcessCommandLine has_any ("WebClient", "DownloadFile", "DownloadData", "DownloadString", "WebRequest", "Shellcode", "http", "https")
| project Timestamp, DeviceName, InitiatingProcessFileName, InitiatingProcessCommandLine, FileName, ProcessCommandLine, RemoteIP, RemoteUrl, RemotePort
| top 100 by Timestamp
```

```kql
// Sentinel table in the same editor (also runs in the Log Analytics demo) — note TimeGenerated
SigninLogs
| where TimeGenerated > ago(1d)
| where ResultType != "0"
| summarize Failures = count() by UserPrincipalName, IPAddress
| where Failures > 10
```

**Go hunt** is a shortcut *into* the editor. On an incident's entity, the Evidence tab or a device timeline event, **Go hunt** / **Hunt for related events** writes and runs a query for you (`search in (DeviceLogonEvents, DeviceProcessEvents, …)` around the selected time), which you then edit.

### 3. Quotas — the numbers to memorise

| Limit | Value |
|---|---|
| Date range | **30 days** of native Defender data; Sentinel tables follow their analytics-tier retention |
| Result set | **100,000 rows** per query |
| Timeout | **10 minutes** per query |
| Results size | **64 MB** (beyond it you get partial results and a message) |
| CPU | Based on tenant size, measured **every 15 minutes**; a warning above **10%**, queries **blocked at 100%** until the next cycle |

These apply **separately** to manual queries and to custom detection rules; the **API** has its own set. The **Query resources report** (button on the hunting page, or **Reports > General**) shows 30 days of query CPU use, marking each query **Low / Medium / High**. Everyone can open it; only **Security Reader and above** see everyone's queries.

==!Contradiction to know:== guided mode calls 10,000 "the maximum number of records", while the quotas table says 100,000 rows. The quotas page and the results page both say ==+100,000==; treat 10,000 as guided mode's sample-size ceiling.

### 4. Save, share and borrow queries

- **Save query > Save as** → pick a folder: **My queries** (only you) or **Shared queries** (everyone in the organization).
- **Rename** or **Delete** from the three-dots menu. Delete is permanent.
- **Share link** creates a URL that opens the query in the editor.
- **Community queries** come from Microsoft's public GitHub repository, reviewed before publishing, grouped in folders such as *Campaigns*, *Collection*, *Defense evasion*.
- With Sentinel connected, Sentinel's saved queries appear under **Queries** in folders marked **Sentinel**, and its functions under **Functions**.
- Threat analytics reports also carry ready-made hunting queries (D3.1.4).

### 5. Work with the results

- **Views:** table, column, pie, line, scatter, area, stacked area and time chart. `render` in the query picks one; otherwise the portal guesses.
- **Export:** in advanced mode, a table exports as an **Excel workbook** and a chart as a **JPEG**. Guided mode's Results tab says **Export** downloads a **CSV**. Two articles, two formats — trust what the button produces.
- **Filters:** tick values, **Add**, then refine. **Right-click** a cell to add it as a filter or copy it.
- **Inspect record:** select a row; a side panel shows the entity details. Its three-dots menu tweaks the query.
- **Timeline:** drawn automatically above results from `Timestamp` or `TimeGenerated`; click a point to filter.
- **Query details:** execution time, resource usage, and full error text.

### 6. Link results to an incident

Hunting found evidence; now it must reach the case file.

1. Run the query. Tick the relevant rows. Select **Link to incident**.
2. **Alert details:** choose **Create new incident** or **Link to an existing incident**, then give an **alert title**, **severity**, **category**, **description** and **recommended actions**.
3. **Entities:** check **Impacted assets** (account, device, mailbox, cloud application, Azure / AWS / GCP resource) and **Related evidence** (process, file, registry value, IP, OAuth app, DNS, security group, URL, mail cluster, mail message). For each, pick an **identifier type** and the **column** that holds it.
4. **Summary** → **Done**.

```kql
// Defender — rows to link. Recipient mailbox/account = impacted assets; sender IP + message = related evidence
EmailEvents
| where Timestamp > ago(1d)
| where EmailDirection == "Inbound" and ThreatTypes has "Malware"
| project Timestamp, NetworkMessageId, SenderFromAddress, SenderIPv4, RecipientEmailAddress, RecipientObjectId, Subject
```

==@One alert is created per unique combination of impacted entities.== Three recipient mailboxes → three alerts in the incident. Permission needed: the same as **managing custom detections**. Sentinel-style **bookmarks are not supported** in advanced hunting — Link to incident is the replacement. You can also link a single **`BehaviorInfo`** record (preview); the wizard pre-fills title, category, description and MITRE techniques from it.

### 7. Take actions on results

Select rows, then **Take actions**. What you can do depends on the columns your query returned.

| Target | Actions | Column the query must return |
|---|---|---|
| **Devices** | Isolate; collect investigation package; run antivirus scan; initiate automated investigation; restrict app execution | `DeviceId` |
| **Identities** | **Disable user**; **reset user authentication** | a SID (`AccountSid` …); `AccountObjectId` for Entra users |
| **Files** | Quarantine | `SHA1` / `SHA256` (or `InitiatingProcess…`) **plus** `DeviceId` |
| **Email** | Move to mailbox folder (Junk, Inbox, Deleted items); delete (**soft** or **hard**); submit to Microsoft; initiate automated investigation | for delete: `EmailDirection` and `SenderFromAddress` |

Every action is recorded in **Action center > History**. Permissions: a Defender for Endpoint role that can submit remediation on devices, a Defender for Office 365 role that can search and purge mail — or unified RBAC **Response (manage)** and **Email & collaboration advanced actions (manage)**.

Current-state caveat: since **1 September 2026** the Defender for **Endpoint** automated investigation (AIR) no longer runs as a separate, manually triggered investigation; Microsoft says to run a full antivirus scan instead. The take-action article still lists "Initiate automated investigation" for devices; Defender for **Office 365** AIR is unchanged.

```kql
// Defender — returns DeviceId and SHA1/SHA256, so Isolate device and Quarantine file are both offered
DeviceFileEvents
| where Timestamp > ago(1d)
| where ActionType == "FileCreated"
| where FolderPath has @"\AppData\Local\Temp\" and FileName endswith ".exe"
| project Timestamp, DeviceId, DeviceName, FileName, FolderPath, SHA1, SHA256, InitiatingProcessFileName
```

```kql
// Defender — returns AccountSid and AccountObjectId, so Disable user / Reset user authentication are offered
IdentityLogonEvents
| where Timestamp > ago(1d)
| where ActionType == "LogonFailed"
| summarize Failures = count(), Devices = dcount(DeviceName) by AccountUpn, AccountSid, AccountObjectId
| where Failures > 20
```

```kql
// Defender — returns the columns that unlock email actions (spam that landed)
EmailEvents
| where Timestamp > ago(1d)
| where ThreatTypes has "Spam"
| project Timestamp, NetworkMessageId, RecipientEmailAddress, EmailDirection, SenderFromAddress, LatestDeliveryAction, LatestDeliveryLocation
```

## Where it lives

| Thing | Path (Defender portal) |
|---|---|
| Advanced hunting | **Investigation & response > Hunting > Advanced hunting** |
| Guided mode | Advanced hunting **> Create new > Query in builder** |
| Saved / shared / community queries | Advanced hunting **> Queries** tab |
| Query resources report | Advanced hunting **> Query resources report**, or **Reports > General** |
| Actions history | **Action center > History** |
| Sentinel-only hunting in the Azure portal | **Microsoft Sentinel > Threat management > Hunting** (separate feature, D3.2) |

Advanced hunting is **only** in the Defender portal. Who can query what:

| Data | Minimum access |
|---|---|
| All advanced hunting data | Entra role **Global Administrator**, **Security Administrator**, **Security Reader** or **Global Reader** (endpoint data still filtered by Defender for Endpoint device-group RBAC) |
| Email & collaboration tables only | unified RBAC **Security operations > Raw data > Email & collaboration metadata (read)**, or an Email & collaboration role group (Security Administrator / Operator / Reader) |
| Alerts & behaviors tables only | unified RBAC **Security operations > Security data > Security data basics (read)** |
| Sentinel tables | Azure role **Microsoft Sentinel Reader** or higher |

Streamed Defender tables tip: if you filter what you stream into Sentinel, use the **time range picker** rather than a time filter in the query — a time filter in the query makes advanced hunting read the (filtered) Sentinel copy.

## Exam traps

- ==!"Guided mode works on Sentinel tables."== ==+Guided mode and Take actions support Defender XDR data only.==
- ==!"Bookmark the rows in advanced hunting."== Bookmarks are a Sentinel **Hunting** feature. ==+In advanced hunting, use Link to incident.==
- ==!"Advanced hunting keeps 90 / 180 days."== ==+30 days== of native Defender data; more only through Sentinel retention.
- **100,000 rows / 10 minutes / 64 MB / 15-minute CPU cycle** — know all four.
- **My queries vs Shared queries:** private vs whole organization. **Community queries** are Microsoft's GitHub set, not your colleagues'.
- **Link to incident creates alerts** — one per unique set of impacted entities — not one alert for all rows.
- **Take action needs the right column.** No `DeviceId` → no device or file actions. Email delete needs `EmailDirection` and `SenderFromAddress`.
- **Disable user / reset user authentication** are identity actions — they need a SID (or `AccountObjectId` for Entra).
- **Link to incident** permission = **manage custom detections** permission.
- **Sentinel data in the unified page** needs **Microsoft Sentinel Reader** at minimum.
