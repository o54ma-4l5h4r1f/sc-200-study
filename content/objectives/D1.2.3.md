## Azure first

- **Azure Monitor** is Azure's general monitoring service. Its **workbooks** feature builds interactive reports from logs and metrics. Sentinel workbooks *are* Azure Monitor workbooks, shown inside Sentinel.
- A **Log Analytics workspace** holds the tables the workbook queries. Workbooks never store data; they query it live.
- **KQL** is the query language each chart runs. You can start a workbook without writing any, from a template.
- The **Content hub** is Sentinel's app store. Installing a **solution** (for example "Microsoft Entra ID") adds its connectors, rules and **workbook templates**.
- Every saved workbook is an **Azure resource** in a **resource group**, so **Azure RBAC** controls who sees and edits it.

New to these? Read the Foundations pages linked above.

## In one sentence

A Sentinel workbook is a saved, interactive dashboard — text, KQL charts, tables and drop-down filters — that you build from a Content hub template or from scratch to watch your security data.

## Why it exists

A SOC manager wants one screen: failed sign-ins by country, top firewall blocks this week, incidents by severity. Writing those queries every morning is waste. A workbook is the **wall of TV screens** in a control room. Each screen runs a fixed query, and the viewer can change the time range or filter with a click.

Workbooks are for **seeing**. They do not raise alerts — analytics rules do that — and they do not take action — automation does that.

## What actually matters

**1. Templates vs saved workbooks.** The **Workbooks** page has two tabs. **Templates** lists templates you got by installing solutions (or standalone workbooks) from the **Content hub**. You don't edit a template directly. **Save** creates your own copy, listed under **My workbooks**, which you then **Edit**. Templates themselves cannot be deleted. Deleting a saved workbook removes it and its customizations permanently. The template stays.

**2. A workbook is an Azure resource that stores JSON, not data.** Saving creates a resource (with the workbook's JSON definition) in the location you pick. Sentinel saves it in the workspace's **resource group**, tagged with the workspace. Because it is a resource, you control access with Azure RBAC. You can also open the JSON in **Advanced Editor**, which is how workbooks get copied between environments.

**3. Check "Required data types" first.** A template's details pane lists the **required data types** (and connectors). With no data in those tables the workbook opens empty. That is a classic "why is my dashboard blank?" question.

**4. Building blocks.** **+ Add** inserts **Text** (Markdown), **Query** (KQL), **Parameters** (time range, drop-downs that filter every query), **Links/tabs** and **Metric**. A query step's visualizations include **grid**, **area**, **bar**, **line**, **pie**, **scatter**, **time chart** and **tiles**. For a query step, set **Data source = Logs** and **Resource type = Log Analytics**, then pick one or more workspaces. Microsoft recommends querying an **ASIM parser** rather than a raw table, so the workbook works for any vendor's data.

**Editing, in practice.** Open the saved workbook and select **Edit**. Each step now shows its own **Edit** button, and the **...** menu lets you move, clone or remove it. Edit mode also shows hidden steps and parameters you don't see in reading mode. Change a query, pick a visualization, then select **Done editing** on that step. Finish with **Save**, or **Save as** to clone the workbook under a new name in the same subscription and resource group. Clones appear under **My workbooks**.

**Sentinel workbooks vs Azure Monitor workbooks.** They are the same engine and the same resource type. The difference is where you open them. Sentinel's **Workbooks** page shows the security templates from the Content hub. **Monitor > Workbooks** shows general Azure templates (VM performance, storage) and can query metrics and other sources too.

**5. Permissions.**

| Need | Role |
|---|---|
| View workbooks | ==@Microsoft Sentinel Reader== (or ==@Workbook Reader==) |
| Create / delete workbooks | ==@Microsoft Sentinel Contributor==, **or** a lesser Sentinel role ==+plus Workbook Contributor== |

All of these go on the **resource group** of the Sentinel workspace. The workbooks article phrases its prerequisite as "at least **Workbook Reader** or **Workbook Contributor** on the resource group"; the roles article frames it through the Sentinel roles. Both are true: the Sentinel roles already include workbook read rights, and the Workbook roles grant workbook rights alone.

**6. Portal and refresh details.**

- **Auto refresh** runs from **5 minutes to 1 day** and is **off** by default. It pauses while you edit and switches off when you close the workbook.
- **Print / Save as PDF** is **Azure portal only**.
- In the Defender portal some visualizations show only in the Azure portal. Use **Open in Azure**.
- Tables in the **Data lake tier** have limited workbook support (the tier comparison is on D1.2.2). Keep dashboard tables in Analytics.
- After ==@March 31, 2027== Sentinel leaves the Azure portal. "Open in Azure" and Azure-only Print/PDF are today's state, not a permanent one.
- You can **pin** a tile made in Log Analytics into a workbook.

Good starter templates: **Microsoft Entra sign-ins** and **Microsoft Entra audit logs** (from the Microsoft Entra ID solution), and a firewall vendor's workbook (for example Palo Alto).

## Where it lives

| Task | Path |
|---|---|
| Sentinel workbooks (Defender portal) | **Microsoft Sentinel > Threat management > Workbooks** |
| Sentinel workbooks (Azure portal) | **Microsoft Sentinel > Threat management > Workbooks** |
| New from scratch | Workbooks > **Add workbook** > **Edit** |
| From a template | Workbooks > **Templates** > select > **Save** > **View saved workbook** > **Edit** |
| Get templates | **Microsoft Sentinel > Content management > Content hub** > install solution |
| Generic Azure Monitor workbooks | **Azure portal > Monitor > Workbooks**, or **Log Analytics workspace > Workbooks** |

A week-over-week chart, straight from the docs:

```kql
SecurityEvent
| where TimeGenerated > ago(14d)
| summarize count() by bin(TimeGenerated, 1d)
| extend Week = iff(TimeGenerated > ago(7d), "This Week", "Last Week"),
         TimeGenerated = iff(TimeGenerated > ago(7d), TimeGenerated, TimeGenerated + 7d)
```

## Exam traps

- "User must view Sentinel workbooks only." ==+Microsoft Sentinel Reader== (or Workbook Reader). ==!Workbook Contributor== is for creating and deleting.
- "Analyst with Responder must save a custom workbook." Add ==+Workbook Contributor==. ==!Don't jump to Sentinel Contributor== — it also edits analytics rules.
- "Workbook template opens with no data." ==+Its required data types/connectors aren't ingesting.==
- "Where do workbook templates come from?" ==+Content hub== (solutions or standalone). Not ==!a built-in list that is always there==.
- "Does deleting the saved workbook delete the template?" ==+No.== Templates can't be deleted.
- "Workbook vs analytics rule vs automation rule." Workbook = ==+visualize==. Analytics rule = detect and alert. Automation rule = act on incidents.
- "Export workbook to PDF from the Defender portal." ==!Not there== — ==+Open in Azure==, then Print.

- **Skip:** unit 3's tour of the Logs page (Queries pane, Query explorer, Export to Power BI). It is KQL/hunting tooling (D3), not workbooks.
- **Skip:** every chart setting (height, width, legend, colour palette, margin/padding on the Style tab). The exam checks that you know the element *types*, not the style options.
- **Skip:** the GitHub repository walkthrough at the end of unit 5. Content hub is the supported route.
- **Skip:** the two long sample queries (multi-source join) — they teach KQL, not workbooks.
- **Skip:** Azure Monitor workbook data sources other than Logs (Resource Graph, Azure Data Explorer, merge, JSON). Sentinel workbooks almost always use **Logs**.
