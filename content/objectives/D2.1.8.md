## Azure first

- **Generative AI / large language model (LLM):** software that reads text and writes text back. It is good at summarising and explaining, and it can be wrong. Everything on this page is an LLM reading your security data and writing for you.
- **Microsoft Security Copilot** is Microsoft's security LLM service. It has a **standalone** portal (`securitycopilot.microsoft.com`) and is **embedded** as a panel inside the Defender, Entra, Purview, Intune and Defender for Cloud portals.
- An **agent** is Copilot running on its own: something triggers it, it works through a task with the permissions you gave its **identity**, and it writes its verdict back. *Agentic AI* = AI that acts, not just answers.
- **Capacity** is paid in **Security Compute Units (SCUs)**. No SCUs, no Copilot.
- **Licence:** needs Security Copilot capacity (bought, or included with Microsoft 365 E5 / E7) plus the product the feature sits on — for example the Phishing Triage Agent needs **Defender for Office 365 Plan 2**. An Azure-only learner has none of this: the screenshots below are the lab.

New to these? Read the Foundations pages linked above.

## In one sentence

Security Copilot is an AI assistant built into the Defender portal that **summarises an incident, recommends response steps, explains scripts and files, writes KQL from plain English and drafts the incident report** — and its **agents** (such as the **Phishing Triage Agent**) triage whole alert types on their own, with a written rationale you can check.

## Why it exists

A new analyst on night shift opens an incident with 40 alerts and an obfuscated PowerShell line. A senior colleague would say in 30 seconds: "It's a phishing-led credential theft, isolate these two laptops, reset this user, here's what that script does." Copilot is that colleague on call. Agents go one step further: they are the junior who clears the pile of user-reported phishing before you arrive, leaving only the real ones.

## What actually matters

**1. The embedded skills in a Defender incident.** Open an incident and the **Copilot** pane (or the **Copilot** tab on the incident page) gives you:

| Skill | What you get | Where |
|---|---|---|
| **Incident summary** | Attack timeline, affected assets, IOCs, threat actor names. Created **automatically** when you open the incident. Covers up to **100** correlated alerts; cached up to **one week** if the incident hasn't changed | Incident page, **Summarize** |
| **Guided response** | Recommended actions in four groups: **triage** (classify as informational, true positive or false positive), **containment**, **investigation**, **remediation**. Cards flag actions already done by attack disruption or AIR. Grayed-out buttons = your role can't do that action. Admins can upload the organisation's own response guidelines | **Recommendations** |
| **Script analysis** | Plain-language explanation of a script or command line, whether it looks malicious, **Show code**, **Show MITRE techniques** | **Analyze** on an event in the attack story or the device timeline |
| **File analysis** | Detections, certificates, API calls, strings in the file | Select a file (for example in the incident graph) > **Analyze** |
| **Device / identity / email summary** | Posture, odd behaviour, sign-ins, role changes | Device, identity or email entity page, **Summarize** |
| **Incident report** | Summary + actions taken + who did what, when | **Report** |
| **Query assistant** | Turns a plain-English question into ready-to-run **KQL** | **Hunting > Advanced hunting** |

Incident summaries run **Always**, **Based on severity level** or **On demand only** — an admin setting (**Settings > Copilot in Defender > Preferences > Incident Summary generation**: *Auto-generate* → *Always* / *Incident severity*, or *Generate on demand*) that trades speed against SCU spend. A cached summary of an unchanged incident is redisplayed **at no cost** whatever the setting. In the standalone portal, put the word **Defender** in the prompt ("…for Defender incident 123") so the Defender capability is picked. Every card has **More actions (…)** → copy, regenerate, or **Open in Security Copilot** to continue in the standalone portal with your own prompts.

**2. Defender Chat (preview).** The **Copilot** button in the portal's top bar opens a chat that knows which page you're on ("which users are in *this* incident?"). For multi-step requests it first shows a **plan you approve or reject**. Only the last **ten** conversations are kept, in your browser.

**3. Agents.** Each agent has a **trigger** (an event or a schedule), an **identity** (a new **Microsoft Entra Agent ID** — recommended — or an existing user account) and **permissions**, and it uses SCUs. Agents are ==!not switched on automatically==: an admin deploys them from **Security Copilot > Security Store** in the Defender portal, and they then appear under **Security Copilot > Agents** (*Ready for setup* → *Agents in use*). The agents Microsoft lists in the Defender portal, plus the cousins in other portals:

| Agent | Portal | What it does |
|---|---|---|
| **Phishing Triage Agent** | Defender | Classifies user-reported phishing as True or False positive with a written rationale. Same agent as the **Security Alert Triage Agent** (preview), which extends triage to some **identity** and **cloud** alerts |
| **Threat Intelligence Briefing Agent** | Defender (Threat analytics banner) / standalone | Builds a threat-intel briefing for your organisation; by default every **7 days**, or run manually |
| **Threat Hunting Assistant** | Defender (Advanced hunting) | Turns a hunting question into KQL, runs it, interprets the results and suggests next steps |
| **Security Analyst Agent** | Defender / standalone | On-demand analysis of Defender or Sentinel data (anomalies, clustering, risk scoring); runs as *you* |
| **Dynamic Threat Detection Agent** (preview) | Defender | Always on, no setup. Finds threats rules missed and raises its own alert with **Detection source = Security Copilot** |
| **Identity Risk Management Agent** (preview) | Entra (**ID Protection > Risky users** > *Start agent*) | Investigates risky users and **suggests** a remediation an admin must approve — no automatic remediation. Needs Entra ID P2 |
| **DLP / Insider Risk Alert Triage agents** | Purview | Prioritise DLP and insider-risk alerts |
| **Conditional Access Optimization Agent** | Entra | Suggests Conditional Access fixes (admin task, not investigation) |

**4. Phishing Triage Agent — the one to know in detail.** Prerequisites: SCU capacity, **Defender for Office 365 Plan 2**, unified RBAC activated for Defender for Office 365, **Monitor reported messages in Outlook** on, the alert policy **Email reported by user as malware or phish** on, and the built-in tuning rule **Auto-Resolve – Email reported by user as malware or phish** turned **off** (the agent ignores alerts that tuning already resolved). Behaviour: it assigns the alert to itself and tags the incident **Agent**. A **false positive** it resolves; a **true positive** it leaves open for an analyst. Its verdict appears as a card in the incident's Copilot/Tasks pane under **Guided Response Triage**, with **View agent activity** showing every step. You can give **feedback once per alert** (*Change classification* → *Why did you change this classification* → *Use this feedback to teach the agent*), and it becomes a **lesson** in the agent's memory.

Who can do what: setting up, pausing, removing the agent and **rejecting feedback** need the Entra **Security Administrator** role. The agent identity needs these unified-RBAC permissions (Security operations group): **Security data basics (read)**, **Alerts (manage)**, **Security Copilot (read)**, **Email & collaboration metadata (read)** and **Email & collaboration content – emails associated with alerts (read)**. Analysts who review its results need the same permissions as the agent or higher.

**5. Capacity (SCUs).**

| Model | How it works |
|---|---|
| **Provisioned** | Bought in advance, minimum **1** SCU, billed **per hour**; refreshes each clock hour, unused SCUs don't roll over |
| **Overage** | Extra SCUs consumed only when provisioned runs out; can be capped or unlimited |
| **Microsoft 365 E5 / E7 inclusion** | **400 SCUs per month per 1,000 paid user licences**, up to **10,000** a month. Auto-provisioned (no Azure setup) as *Default Security Copilot Capacity*. Resets monthly, no rollover. Phased rollout began **18 November 2025**. Sentinel-only customers without E5/E7 are **not** eligible |

**6. Prompting and trust.** A good prompt has four parts: **goal**, **context**, **expectations**, **source**. Copilot's **process log** shows which plugin it used and that **safety checks** ran. Always verify the output — every card has 👍 / 👎 feedback. The standalone vocabulary: **session** (one conversation), **prompt**, **promptbook** (a saved sequence of prompts), **plugin** (a data source such as Defender XDR or *Natural Language to KQL*), **workspace**, **agent**, and roles **Security Copilot Owner** / **Contributor**.

## Where it lives

| Task | Path |
|---|---|
| Incident summary, guided response, report | Defender portal > open an incident > **Copilot** tab / pane |
| Script analysis | Incident > attack story > select an event > **Analyze** (or device timeline > event > **Analyze**) |
| KQL from English | **Hunting > Advanced hunting** > Copilot |
| Defender Chat | **Copilot** button, top bar of the Defender portal |
| Phishing Triage Agent | Set up: **Security Copilot > Security Store**, or **Investigation & response > Incidents & alerts > Incidents** > Phishing Triage card > **Set up agent**. Review: filter the queue by the **Agent** tag. Manage: **Security Copilot > Agents** > *Agents in use* > **Go to agent** (Overview / Performance tabs, ellipsis > Edit agent > Feedback) |
| Incident summary settings | **Settings > Copilot in Defender > Preferences > Incident Summary generation** |
| Threat Intelligence Briefing Agent | **Threat intelligence > Threat analytics** > agent banner > **Set up agent** / **View full brief** |
| Standalone portal | `securitycopilot.microsoft.com` (sessions, promptbooks, plugins, owner settings, usage monitoring) |
| Change capacity | Security Copilot portal or the Azure portal (provisioned SCUs); usage monitoring dashboard in the standalone portal |

Sample standalone prompts from the docs:

```text
Summarize incident {incident number} and conclude with a set of recommendations
Provide a summary for Defender incident {incident ID}.
Generate guided responses and recommendations for Defender incident {incident ID}.
Identify the scripts in Defender incident {incident ID}. Are these malicious scripts?
```

## Exam traps

- ==!Copilot takes the response action for you.== In the embedded pane it ==+recommends==; you act. Agents act only within the identity and permissions you gave them.
- ==!The Phishing Triage Agent closes true positives.== No — it ==+resolves false positives== and leaves ==+true positives open== for an analyst.
- Agent not triaging anything? Check the ==@Email reported by user as malware or phish== alert policy and that ==@Auto-Resolve== tuning is **off**.
- Phishing Triage needs ==@Defender for Office 365 Plan 2==, not Plan 1.
- ==!Unused provisioned SCUs carry over.== They expire at the end of each hour; E5 inclusion resets monthly.
- E5/E7 inclusion maths: ==@400 SCUs / 1,000 licences / month==, max ==@10,000==. 400 licences → 160 SCUs.
- ==!Script analysis is in advanced hunting.== It is on events in the ==+attack story== and the ==+device timeline==. The KQL generator is the one in advanced hunting.
- Guided response's four categories: **triage, containment, investigation, remediation** — not "detect, protect, respond".
- Copilot output can be wrong. Questions that ask what to do with a summary want ==+verify, then act==.
- ==!Agents start working as soon as you have SCUs.== An admin must ==+deploy and set up== each one (Security Store / Agents page). The exception is the **Dynamic Threat Detection Agent**, which is always on.
- An alert whose **Detection source** is ==@Security Copilot== came from the Dynamic Threat Detection Agent, not from a rule you wrote.
- Setting up or removing the Phishing Triage Agent, or rejecting its feedback = ==@Security Administrator== (Entra). Not Security Operator.

## Skip

- **`security-copilot-getting-started` unit 6 "Enable Security Copilot"** — onboarding steps are admin work, off-blueprint. Know the capacity models above.
- **`security-copilot-describe-core-features` unit 4 (workspaces) and unit 7 (knowledge base connections)** — off-blueprint. One line: a workspace is a scoped environment inside the tenant.
- **Owner settings screens** (data sharing, audit logging, file upload, plugin restrictions, role assignment) in the standalone-experience unit. Admin configuration, not investigation.
- **`security-copilot-embedded-experiences` unit 5 (Intune)** and **`security-copilot-interactive-guides` unit 9 (Conditional Access agent)** — off-blueprint for an analyst.
- **Custom plugin and custom agent building** (YAML manifests, *Build your own agents*). Developer territory.
- **Purview eDiscovery and Communication Compliance Copilot summaries** — shown below because they're in mapped units, but D2.1.2 covers Purview alerts; here you only need "Copilot is embedded there too".
- **Defender for Cloud "Reduce risk with Copilot" and delegate-by-email** screens — posture work, not incident investigation.
- **Prices per SCU.** They change; the exam asks how capacity works, not what it costs.
