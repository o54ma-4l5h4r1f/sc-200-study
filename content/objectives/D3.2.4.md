## Azure first

- A **Jupyter notebook** is a document made of **cells**. Some cells hold text, others hold code (usually **Python**). You run a cell and its output (a table or chart) appears underneath. The code actually runs on a separate computer called the **kernel**.
- **Azure Machine Learning (AML)** is an Azure service that hosts notebooks. Its **workspace** is an Azure resource; its **compute instance** is the VM that runs the kernel and costs money while running.
- **Visual Studio Code (VS Code)** is Microsoft's free code editor. Extensions add features. The **Microsoft Sentinel extension** adds data lake notebooks, and **GitHub Copilot** adds an AI chat with an **Agent mode**.
- The **Sentinel data lake** is the cheap long-term tier (D1.2.2). Lake notebooks use **Apache Spark** (PySpark), a system that splits big data work across many machines.
- **Microsoft Entra roles** such as **Security Reader** apply tenant-wide. **Azure RBAC** roles such as **Microsoft Sentinel Contributor** apply to one resource.

New to these? Read the Foundations pages linked above.

## In one sentence

**Notebooks** let you hunt with code. Python pulls Sentinel data with KQL, enriches it, runs maths or machine learning and draws charts. The **Sentinel MCP Server** is a Microsoft-hosted endpoint that lets an AI assistant (for example GitHub Copilot in VS Code) find tables, write and run KQL, and analyze entities for you in plain English.

## Why it exists

The Hunting page (D3.2.1) is a torch; some hunts need a workshop. Joining Sentinel data to an HR spreadsheet, looking up 5,000 IPs in a threat-intel service, or drawing a process tree is beyond KQL alone. A notebook is the workshop bench: data, code, results and notes on one page you can rerun and share.

The MCP Server solves a different problem: not knowing which of hundreds of tables holds the answer, or how to write the KQL. MCP (**Model Context Protocol**) is an open standard for plugging tools into AI assistants. Ask "find sign-in failures in the last 24 hours". The assistant calls `search_tables`, writes KQL, runs it with `query_lake`, fixes its own errors and answers.

## What actually matters

**1. Notebook basics (training units 3–4).** A notebook has two parts: the **browser interface** where you type and see results, and the **kernel** that runs the code. In Sentinel the kernel runs on an **Azure VM** inside **Azure Machine Learning**. Microsoft ships notebook **templates**, such as *A Getting Started Guide For Microsoft Sentinel ML Notebooks*, *Credential Scan on Azure Log Analytics* and *Guided Investigation - Process Alerts*. More are in the `Azure/Azure-Sentinel-Notebooks` GitHub repository. Run cells **in order**; skipping one causes errors. **Shift+Enter** runs a cell. Restarting the kernel wipes all variables.

**2. Use a notebook when the portal can't:** Python **machine learning**, custom **timelines** and **process trees**, and data **outside** Sentinel (on-premises sets, HR databases, external TI).

**3. The two libraries (training unit 2).**

| Library | What it is | Remember |
|---|---|---|
| ==@Kqlmagic== | a thin wrapper to run KQL queries inside a notebook | "the glue": KQL in, results out |
| ==@MSTICPy== | **Microsoft Threat Intelligence Center** Python security tools | three jobs: **acquire and enrich**, **analyze**, **visualize** data. Has predefined queries (for example `list_logons_by_account`), TI lookups, timelines, process trees |

```python
# MSTICPy pattern from training units 4-5 (Azure ML notebook, Python 3.10 kernel)
import msticpy as mp
mp.init_notebook()                       # first run writes msticpyconfig.yaml
qry_prov = mp.QueryProvider("MSSentinel")
qry_prov.connect(mp.WorkspaceConfig())   # authenticate to the workspace
test_query = """
SecurityEvent
| where TimeGenerated > ago(1d)
| where EventID == 4625
| summarize Failures = count() by Account, IpAddress
| top 20 by Failures
"""
test_df = qry_prov.exec_query(test_query)   # returns a pandas DataFrame
test_df.head()
```

The KQL inside is ordinary. You can paste it into Logs first to test it:

```kql
SecurityEvent
| where TimeGenerated > ago(1d)
| where EventID == 4625
| summarize Failures = count() by Account, IpAddress
| top 20 by Failures
```

**4. Setting up Sentinel Notebooks (row A).** Path: **Microsoft Sentinel > Threat management > Notebooks** (both portals). Steps: **Configure Azure Machine Learning > Create a new AML workspace**. Choose subscription, resource group, name, region, storage account, key vault, Application Insights and container registry (**None** is fine). Then **Templates** tab > pick a notebook > **Create from template** > **Save**, then **Launch notebook**. In AML studio, create or start a **compute instance** and pick the kernel. Only AML workspaces in the **same subscription** can be chosen. A **private endpoint** option exists for locked-down networks.

| Role | Why |
|---|---|
| ==@Microsoft Sentinel Contributor== | to **save and launch** notebooks from Sentinel |
| Sentinel Reader / Responder / Contributor | to **see** the Notebooks page |
| **Owner** or **Contributor** on the resource group | to **create** the AML workspace |
| **Contributor** on the AML workspace | to **run** notebooks in it |

==!Compute instances bill while they run.== Stop them after a lab.

**5. Data lake notebooks (row B).** Notebooks on the **data lake** don't run in AML. Install **VS Code** and the **Microsoft Sentinel** extension, select the Sentinel icon and sign in. The left pane lists **Lake tables** (System, Custom, Federated) and **Jobs**. Create a Jupyter notebook. Use `MicrosoftSentinelProvider(spark)` to `read_table()` and `save_as_table()`. Choose the **Microsoft Sentinel** runtime and a pool: **Small** (testing), **Medium** (joins, ETL, ML training), **Large** (deep learning, big shuffles). The first session takes **3–5 minutes** to start; the limits table says 5–6.

```python
from sentinel_lake.providers import MicrosoftSentinelProvider
data_provider = MicrosoftSentinelProvider(spark)

df = data_provider.read_table("EntraGroups")          # a lake table
df_out = df.filter(df.mail.isNotNull()).select("displayName", "mail", "tenantId")
data_provider.save_as_table(df_out, "EntraGroups_Processed_SPRK",
                            write_options={"mode": "overwrite"})
```

Key limits: language **Python** only. Only **Azure Synapse libraries 3.4** plus the Sentinel provider; ==!no `pip install` or custom libraries==. Interactive session idles out after **20 minutes** (the extension's own timeout setting defaults to 30). **Notebook jobs** time out at **8 hours**, with at most **3 concurrent**; extra jobs **queue**. The UI shows up to **100,000** rows. ==!You can't delete an Analytics-tier custom table from a notebook==; use Log Analytics. Writing to Analytics or lake tables needs **Security Operator**, **Security Administrator** or **Global Administrator**. Creating new Analytics tables also needs **Log Analytics Contributor** for the lake's managed identity, as with KQL jobs (D3.2.2). Scheduled **notebook jobs** are created from the VS Code extension and can take **parameters** (reuse one notebook for different users or time ranges). They appear on **Data lake exploration > Jobs** with Job type **Notebook**, but are ==!view-only== there: no create or edit. **Reading** lake data needs an Entra role such as **Security Reader** (all workspaces) or an Azure RBAC role such as **Log Analytics Reader** or **Microsoft Sentinel Reader** on one workspace. Optional **row-level scoping** (preview) can trim what a scoped user's query returns.

**6. The Sentinel MCP Server (row C).** It is fully **hosted by Microsoft**. There is nothing to deploy, and sign-in uses **Microsoft Entra**. Tools come in **collections**, each with its own URL:

| Collection | URL | Main tools | Needs |
|---|---|---|---|
| ==@Data exploration== | `https://sentinel.microsoft.com/mcp/data-exploration` | `search_tables`, `query_lake`, `list_sentinel_workspaces`, entity analyzer (`analyze_user_entity`, `analyze_url_entity`, `get_entity_analysis`), graph tools (preview) | data lake onboarding |
| ==@Triage== | `https://sentinel.microsoft.com/mcp/triage` | `ListIncidents`, `GetIncidentById`, `ListAlerts`, `RunAdvancedHuntingQuery`, `FetchAdvancedHuntingTablesOverview`, Defender file, IP, device and user tools | Defender XDR / MDE, or Sentinel in the Defender portal |
| **Security Copilot agent creation** | `https://sentinel.microsoft.com/mcp/security-copilot-agent-creation` | build Security Copilot agents | Security Copilot |

Run `list_sentinel_workspaces` first: the other data exploration tools need a workspace ID. The preview **graph tools** are `find_blastradius`, `find_walkable_paths`, `find_exposure_perimeter`, `find_connected_nodes`, `find_nodes` and `get_graph_context` (blast radius and attack paths, D3.1.5). You can also build **custom MCP tools** from saved advanced hunting KQL queries.

**7. Connecting it in VS Code** (the bullet's "connection"):

1. **Ctrl+Shift+P** > `MCP: Add Server`.
2. Choose **HTTP (HTTP or Server-Sent Events)**.
3. Paste a collection URL (case sensitive), for example the data-exploration URL.
4. Give a **Server ID** (for example `Microsoft Sentinel MCP server`). Choose all workspaces or only the current one.
5. **Allow** the sign-in with an account that has at least ==@Security Reader==.
6. Open **View > Chat** (**Ctrl+Alt+I**), switch to **Agent** mode, and select **Configure Tools** to confirm the Sentinel tools are listed.

Other clients for **data exploration**: **Security Copilot**, **Copilot Studio**, **Microsoft Foundry**. The **triage** collection lists ==!only VS Code== as a supported client. Access needs at least **Security Reader** (or Security Operator / Security Administrator), for users, managed identities or service principals. **Triage** tools use your existing permissions. The **entity analyzer** also needs **Security Copilot Contributor** because it consumes Security Compute Units (SCUs). Turning MCP access off means **contacting Microsoft support**.

**8. What MCP is not.** Not a data connector, not a notebook kernel, not storage. It is a set of tools an AI model calls. Limits: `analyze_user_entity` covers at most **7 days**, works only for users with a **Microsoft Entra object ID** (not on-premises-only AD users), and needs `AlertEvidence`, `SigninLogs`, `CloudAppEvents` and `IdentityInfo` in the lake. Run at most about **five** analyses at once. The **triage** collection ==!can't query the data lake== (use data exploration) and works only in your **home tenant** (no guest or delegated access). Sentinel users can't pick which workspace triage uses. Graph tools need read-only **Security Exposure Management** access. Parts are **prerelease**.

**9. Notebook or MCP?** Notebook for repeatable code, ML, custom charts or outside data. MCP agent for a fast plain-English answer, table discovery or entity verdicts. In VS Code they sit side by side: the agent drafts the KQL, the notebook makes it repeatable.

## Where it lives

| Task | Where |
|---|---|
| Sentinel notebooks (AML) | Defender: **Microsoft Sentinel > Threat management > Notebooks**. Azure: **Microsoft Sentinel > Threat management > Notebooks** |
| Create AML workspace | Notebooks > **Configure Azure Machine Learning > Create a new AML workspace** |
| Launch a template | Notebooks > **Templates** > **Create from template** > **Save** > **Launch notebook** |
| Data lake notebooks | VS Code > Extensions > **Microsoft Sentinel** > Sentinel icon > **Lake tables / Jobs** |
| Notebook jobs (view) | Defender: **Microsoft Sentinel > Data lake exploration > Jobs** (Job type **Notebook**) |
| Add the MCP Server | VS Code: **Ctrl+Shift+P** > `MCP: Add Server` > **HTTP** > collection URL |
| Use MCP tools | VS Code **Chat** (**Ctrl+Alt+I**) > **Agent** mode > **Configure Tools** |

## Exam traps

- "Which library provides MSTIC's hunting tools: TI lookups, timelines, process trees?" ==+MSTICPy.== "Which library is the simple KQL wrapper?" ==+Kqlmagic.==
- "Where does a Sentinel notebook's kernel run?" ==+On an Azure Machine Learning compute instance (an Azure VM).== ==!Not inside the Log Analytics workspace.==
- "First step before launching a Sentinel notebook template." ==+Configure Azure Machine Learning / create an AML workspace.==
- "Role to save and launch notebooks from Sentinel." ==+Microsoft Sentinel Contributor== (plus Contributor on the AML workspace).
- "Notebook to analyze 2 years of lake-only firewall data with Spark." ==+VS Code with the Microsoft Sentinel extension, MicrosoftSentinelProvider.== ==!Not the Azure ML Sentinel Notebooks page.==
- "`pip install` a package in a lake notebook." ==!Not supported.==
- "Connect GitHub Copilot to Sentinel data in natural language." ==+Add the Sentinel MCP Server in VS Code (`MCP: Add Server` > HTTP > collection URL), sign in, use Agent mode.==
- "Minimum role to list and invoke Sentinel MCP tools." ==+Security Reader.== ==!Global Administrator is not required.==
- "Triage collection to query 6-month-old lake data." ==!It can't query the lake.== ==+Use the data exploration collection (`query_lake`).==
- "You must deploy an MCP server VM." ==!No== — it is Microsoft-hosted, Entra-authenticated.
- "Entity analyzer returns an SCU error." ==+Needs Security Copilot Contributor== (it consumes SCUs).
- "Which MCP tool should the agent call before any other data exploration tool?" ==+`list_sentinel_workspaces`== (the others need a workspace ID).
- "Edit a scheduled notebook job's schedule on the Defender Jobs page." ==!View-only there.== ==+Edit and republish from the VS Code extension.==

## Skip

- **Skip:** training unit 4's 28-step click path through AML studio (compute name, workload type, Python 3.10 kernel, clearing outputs). Know: AML workspace, then template, then compute instance, then kernel, then run cells in order.
- **Skip:** the Python details in unit 5 (`lookup_res`, `.head()`, plotting calls). Know what MSTICPy does, not its function signatures.
- **Skip:** private-endpoint networking for AML (jump box, Bastion, private DNS zones). Azure networking, not hunting.
- **Skip:** the long lists of Python libraries (pandas, matplotlib, bokeh and friends). Recognize the names only.
- **Skip:** the 180-row supported-tables list for `search_tables`, every triage tool's parameters, and graph-tool parameters. Know the collection names, what each reaches, and the key tools (`search_tables`, `query_lake`, `list_sentinel_workspaces`, entity analyzer, `RunAdvancedHuntingQuery`).
- **Skip:** the agent-creation collection, custom MCP tools, and custom graphs/GQL in the VS Code extension. Know they exist.
- **Coverage note:** the training module (units 2–5) teaches only Azure ML notebooks, Kqlmagic and MSTICPy. Data lake notebooks and the **entire MCP Server half** come from product documentation.
