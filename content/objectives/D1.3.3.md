## Azure first

- **Windows Event Forwarding (WEF)** is built into Windows. It is not an Azure feature. It copies chosen events from many Windows machines to one **Windows Event Collector (WEC)** server, using Windows Remote Management (WinRM, the WS-Management protocol).
- The **Azure Monitor Agent (AMA)** is installed ==@only on the WEC server==, not on every source machine. A **data collection rule (DCR)** tells it to read the collector's **ForwardedEvents** log.
- If the WEC server is on-premises, it must first be connected to Azure with **Azure Arc**.
- The events land in the **`WindowsEvent`** table of the Sentinel workspace — not `SecurityEvent`.

New to these? Read the Foundations pages linked above.

## In one sentence

WEF lets hundreds of Windows machines push their events to one collector server, and the **Windows Forwarded Events** connector puts AMA on that collector so Sentinel receives everything in the `WindowsEvent` table.

## Why it exists

Picture a chain of shops. Instead of a courier visiting every shop, each shop drops its receipts at a regional depot. One courier collects from the depot. WEF is the drop-off; the WEC server is the depot; AMA is the single courier.

You choose this when you **can't or won't install an agent on every machine** — thousands of workstations, locked-down servers, or a team that already runs WEF. It also suits organisations with a WEF design they don't want to rebuild.

The price: the data lands in a different table, so some built-in Sentinel content won't fire without changes.

## What actually matters

**1. The pieces and their names.**

| Piece | What it is |
|---|---|
| **Event source** (WEF client) | Any Windows machine whose events are forwarded. Uses the built-in forwarding client. |
| **Windows Event Collector (WEC)** | The server that receives and stores forwarded events in a local event log, by default **ForwardedEvents**. |
| **Subscription** | The definition on the WEC of which events to collect (an XPath/XML query) and from whom. |
| **Windows Forwarded Events connector** | The Sentinel connector. Creates a DCR for AMA on the WEC. Writes `WindowsEvent`. |

**2. Two subscription types — a classic exam pair.**

- **Source-initiated (push):** the subscription is defined on the collector **without** listing sources. Sources are pointed at the collector by a **Group Policy** setting (**SubscriptionManager**). The simplest and most scalable choice. Access is controlled by an ACL of **computer accounts or security groups of computer accounts** — not user accounts.
- **Collector-initiated (pull):** the collector's subscription lists every source machine by name. Use it when you know all sources in advance.

A subscription is push or pull, never both.

**3. Planning the collector.** Microsoft's guidance for a stable WEC on commodity hardware is about **3,000 events per second** across all subscriptions. Its limits are disk speed (it writes every event to a local EVTX file), open TCP ports, and registry size (one key per source machine ever seen). Past **50,000 lifetime sources**, Event Viewer can't manage the subscription and you must use `wecutil.exe`. For high availability, configure **two WEC servers** with the same subscription; sources send to both. Note AMA on Windows handles about **5,000 events per second**, so size the WEC with the agent in mind.

**4. Security of the transport.** In a domain, WEF traffic is **encrypted with Kerberos by default** (NTLM fallback can be disabled), and client and collector authenticate each other — even if "HTTP" is selected. HTTPS (port 5986) is for **certificate-based** authentication when Kerberos isn't possible, for example workgroup machines.

**5. Gotchas that cost events.**

- WEF is passive. It ==!can't enable audit policy== or turn on disabled logs. Windows must already be generating the events.
- To forward the **Security log**, add **NETWORK SERVICE** to the **Event Log Readers** group on the sources.
- By default a subscription forwards only events created **after** the client received it. "Read existing events" changes that.
- If the client is offline and its local log wraps, events are lost silently — no gap marker.
- Default format is **Rendered Text** (bigger). The **Events** (binary XML) format can more than double a collector's capacity.
- Delivery options: **Normal** (pull, batches of 5, 15-minute timeout), **Minimize bandwidth** (push, 6 hours), **Minimize latency** (push, 30 seconds).

**6. The Sentinel side.** Prerequisites: WEC enabled and running; AMA on the WEC (Arc if not in Azure); read/write on the workspace; the **Windows Forwarded Events** solution from Content hub. Microsoft recommends installing the **ASIM** parsers (normalising KQL functions) so content can read `WindowsEvent`. The `WindowsEvent` table stores event fields in a parsed `EventData` column (with `RawEventData` if parsing fails).

## Where it lives

**On Windows (collector):**

```powershell
winrm qc -q        # enable WinRM listener
wecutil qc /q      # configure the Windows Event Collector service
wecutil ss "SubName" /cf:Events   # switch a subscription to the compact Events format
```

Subscriptions: **Event Viewer > Subscriptions** on the WEC, or `wecutil cs subscription.xml` from a subscription XML file.

**On sources (Group Policy):** **Computer Configuration > Administrative Templates > Windows Components > Event Forwarding** > the **SubscriptionManager** setting (Microsoft's docs name it this way; the GPO editor labels it "Configure target Subscription Manager") — the address of the WEC.

**In Sentinel (Defender portal):** **Microsoft Sentinel > Content management > Content hub** > install **Windows Forwarded Events**, then **Microsoft Sentinel > Configuration > Data connectors > Windows Forwarded Events > Open connector page > +Create data collection rule**. On **Resources** pick the WEC server. Same path under **Microsoft Sentinel** in the Azure portal.

Query the result:

```kql
WindowsEvent
| where TimeGenerated > ago(1h)
| where Channel == "Security" and EventID == 4625
| project TimeGenerated, Computer, EventID, EventData
```

## Exam traps

- "WEF-forwarded Security events appear in `SecurityEvent`." ==!False.== They go to ==+`WindowsEvent`==, even events that came from the Security log.
- "Install AMA on every source machine for WEF." ==!No== — ==+only on the WEC server==. That is the whole point.
- "Built-in rule for 4625 doesn't fire on forwarded data." Expected: the rule queries `SecurityEvent`. Fix: adapt the query, use ASIM parsers, or switch to **Windows Security Events via AMA**.
- "Point thousands of sources at a collector without listing them." ==+Source-initiated subscription + GPO.== Collector-initiated needs every source named.
- "Subscription ACL contains user accounts." ==!No== — computer accounts or groups of them.
- "WEF over HTTP is unencrypted." ==!False in a domain== — Kerberos encrypts it.
- "WEF turns on auditing." ==!False== — audit policy must already be set.
