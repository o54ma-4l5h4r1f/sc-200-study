## Azure first

- **Microsoft Defender for Endpoint (MDE)** is the security agent on laptops and servers: antivirus, plus **EDR** (endpoint detection and response — a flight recorder of what every process did). Its settings live in the Defender portal under **Settings > Endpoints**.
- **Microsoft Defender Antivirus** is the antivirus built into Windows. Many advanced features only work when it is the **active** antivirus with **cloud-based protection** on.
- An **indicator** is your own allow/block list entry (a file hash, IP, URL, domain or certificate). Several switches on this page exist only to turn indicator types on.
- **Live response** is a remote command shell from the portal into a device, used during an investigation.
- **Licence:** MDE is a Microsoft 365 product. An Azure-only learner can still meet it through **Defender for Servers** in Defender for Cloud, which gives servers the same benefits as MDE Plan 2. Otherwise, treat the screenshots as the lab.

New to these? Read the Foundations pages linked above.

## In one sentence

**Settings > Endpoints > Advanced features** is one long page of tenant-wide **On/Off switches** that turn Defender for Endpoint capabilities and integrations on or off for the whole organisation — then **Save preferences**.

## Why it exists

Think of the main fuse box in a building. Each room has its own light switches (device policies, device groups). The fuse box decides whether a whole circuit exists at all. If the **Custom network indicators** fuse is off, no amount of URL block entries will ever fire. Advanced features is that fuse box: switch first, then configure the feature elsewhere.

## What actually matters

The page has about 25 switches. Group them; the exam asks "which switch do I need for X?".

| Group | Switch | What it does — the one fact to keep |
|---|---|---|
| **Unlock indicators** | **Allow or block file** | Lets you block/allow files by hash. Needs Defender Antivirus **active** + **cloud-based protection**. Blocked files cannot be read, written or run |
| | **Custom network indicators** | Lets IP/URL/domain indicators allow or block traffic. Windows 10 1709+ or Windows 11 |
| **Response tools** | **Live response** | Analysts with the right permission can open a remote shell on **devices** |
| | **Live response for servers** | Same, for **servers** — a separate switch |
| | **Live response unsigned script execution** | Allows **unsigned** scripts in live response |
| | **Isolation Exclusion Rules** | Defines processes/IPs that still work when a device is put in **selective isolation** (Windows and Mac rules). Full isolation ignores them. Turning the feature on ==!empties the old built-in Teams/Outlook/Skype exclusions== — re-add them as rules if needed. Needs **Security Administrator** or **Manage security settings** |
| | **Automatic attack disruption** | The docs page lists it here too. It contains compromised assets automatically; configuration is taught in D1.1.8 |
| | **Download quarantined files** | Keeps quarantined files so they can be downloaded. ==@On by default== |
| **Alert handling** | **Automatically resolve alerts** | Resolves alerts where no threat was found or the threat was remediated. ==!Never overwrites an analyst's In progress / Resolved status== |
| | **Restrict correlation to within scoped device groups** | Alerts from different device groups no longer join one incident. For local SOCs. Affects **future** correlation only. Microsoft advises against it unless needed |
| **Prevention** | **EDR in block mode** | EDR blocks malicious artifacts **even when Defender Antivirus is in passive mode** (another vendor's AV is primary) |
| | **Tamper protection** | Locks Defender Antivirus settings so apps or attackers cannot turn protection off |
| | **Web content filtering** | Turns on category-based web blocking; you then create policies |
| **Investigation context** | **Show user details** | Shows Entra ID picture, name, title, department on user entities |
| | **Skype for Business integration** | Contact the user by Skype, email or phone; keep Outlook/Skype open during isolation |
| | **Hide potential duplicate device records** | Hides duplicates (matched by hostname + last seen) from inventory. ==@On by default==, tenant wide |
| **Integrations** | **Microsoft Defender for Cloud Apps** | Forwards MDE signals for cloud-app discovery |
| | **Microsoft Intune connection** | Shares device risk with Intune for **device risk-based Conditional Access**. Must be enabled in **both** Intune and MDE |
| | **Share endpoint alerts with Microsoft Compliance Center** | Sends endpoint alerts to Purview **insider risk management** |
| | **Unified audit log** | Writes audit records to the Microsoft 365 audit log (Purview Audit) |
| | **Device discovery** | Onboarded devices find **unmanaged** devices on the network |
| **Platform** | **Default to streamlined connectivity** | Makes the streamlined onboarding package the default |
| | **Authenticated telemetry** | Stops spoofed telemetry reaching your dashboard |
| | **Preview features** | Turns on preview features |
| | **Endpoint Attack Notifications** | Microsoft hunts your endpoint data and notifies you of critical threats (the old *Microsoft Threat Experts - Targeted Attack Notifications*) |

Three more facts beginners miss:

- **Automated investigation is not a switch any more.** The **Automated Investigation** option was removed from advanced features; it is on by default. From **1 September 2026**, AIR in Defender for Endpoint no longer runs as a separate investigation experience and cannot be triggered manually; its detection and response are part of the default antivirus stack. Automation **levels** are still set per device group (D1.1.9). AIR for Defender for Office 365 is unaffected.
- **Switches are tenant-wide.** Device groups scope *who sees what*; advanced features are on or off for everyone.
- **Some switches need another licence or product** — Intune for the Intune connection, Defender for Cloud Apps for its integration.

No PowerShell cmdlet sets these switches. **Tamper protection** can also be managed from Intune; that is a D1.1.6 topic.

> **Training vs product:** training unit *Configure environment advanced features* lists an **Automated investigation** switch, says **Live response requires Automated investigation**, and lists **Always remediate PUA**, **Microsoft Defender for Identity integration**, **Office 365 Threat Intelligence connection** and **Microsoft Threat Experts - Targeted Attack Notifications**. The current docs page does not: Automated Investigation was **removed** (on by default), and Threat Experts notifications are now **Endpoint Attack Notifications**. The product wins. If an exam option says "turn on Automated investigation in Advanced features", treat it as the old answer.

## Exam traps

- "Block this file hash everywhere" fails → ==+turn on Allow or block file== first. Also needs Defender Antivirus active + cloud protection.
- "URL block indicator does nothing" → ==+Custom network indicators== on **and** network protection in **block mode**.
- Another vendor's antivirus is primary; you still want MDE to block post-breach artifacts → ==+EDR in block mode==. ==!Not Tamper protection.==
- "Stop malware from turning off Defender Antivirus" → ==+Tamper protection==.
- "Live response works on laptops but not on servers" → ==+Live response for servers== is a separate switch.
- "Run our own unsigned PowerShell in live response" → ==+Live response unsigned script execution==.
- "Regional SOC must act on incidents for its own device group only" → ==+Restrict correlation to within scoped device groups==. Global SOC then sees **more**, smaller incidents.
- "Auto-resolve will overwrite my Resolved status" → ==!false==.
- "Device risk should block access to Microsoft 365" → ==+Microsoft Intune connection== (enabled in both portals) + Conditional Access.

## Skip

- **Skip:** training module *Deploy the Microsoft Defender for Endpoint environment* units 2 (*Create your environment*), 3 (*Understand operating systems compatibility and features*) and 4 (*Onboard devices*). They are off-blueprint for SC-200 — onboarding is an endpoint-admin task.
- **Skip:** module *Configure and manage automation using Microsoft Defender for Endpoint* unit 5 (*Block at risk devices*) — Intune/Conditional Access detail, off-blueprint.
- **Skip:** data-residency notes ("forwarded data is stored in the same location as…") and the licence fine print for Intune. Know that the Intune connection needs Intune and is enabled on both sides.
- **Skip:** the Skype for Business detail. Skype is deprecated; know the switch exists.
- **Skip:** the isolation exclusion field syntax (process path examples, IPv6 forms). Know that selective isolation uses global rules and full isolation ignores them.
