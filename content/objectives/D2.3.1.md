## Azure first

- **Microsoft 365** is the bundle of cloud apps — Exchange Online (mail), SharePoint and OneDrive (files), Teams, Copilot — that shares one **Microsoft Entra** tenant with your Azure subscriptions.
- **Microsoft Purview** is Microsoft's compliance family. Its portal is `purview.microsoft.com`. **Audit** is one Purview solution; so is eDiscovery (D2.3.2).
- **Licences decide what is recorded.** Audit (Standard) comes with most Microsoft 365 / Office 365 plans. Audit (Premium) comes with **E5**-level licences (Microsoft 365 E5, Office 365 E5, Purview Suite, or the E5 eDiscovery and Audit add-on) — and applies per **user**.
- **Exchange Online PowerShell** is the command-line way into Exchange. The audit search cmdlet `Search-UnifiedAuditLog` lives there, not in Azure PowerShell.
- Without a Microsoft 365 tenant you cannot run this. It is licence-blocked for an Azure-only learner — study the screenshots.

New to these? Read the Foundations pages linked above.

## In one sentence

**Microsoft Purview Audit** is the searchable **unified audit log** of what users and admins did across Microsoft 365 — sign-ins, mail access, file shares, setting changes, Copilot prompts — kept **180 days** in **Audit (Standard)** and longer — plus retention policies and extra forensic detail — in **Audit (Premium)**.

## Why it exists

Think of an office building's **visitor book and door-badge log**. It does not stop anyone or ring an alarm. Days later, when something is missing, you read it to answer "who opened which door, from where, and when?".

Purview Audit is that log for Microsoft 365. After a phishing-led account takeover, the SOC asks: which mailbox did the attacker read? Did they create an inbox forwarding rule? Did they share files externally? Did they ask Copilot to summarise patient records? Defender alerts tell you *that* something happened. Audit records tell you *exactly what* the account did.

One log, many writers. The **tier** decides how long records live and which high-value events exist. The **search** looks the same whichever tier you have.

## What actually matters

**1. Standard vs Premium.**

| Capability | Audit (Standard) | Audit (Premium) |
|---|---|---|
| On by default, portal search, `Search-UnifiedAuditLog`, CSV export, Management Activity API | Yes | Yes |
| Default retention | **180 days** | 180 days, but **1 year** for Entra ID, Exchange, SharePoint, OneDrive activity |
| Audit log retention policies | No | Yes — up to **1 year**; **10 years** with the 10-Year Audit Log Retention add-on |
| `MailItemsAccessed` (which mail was read) | **Yes** for E3/E5 users, per the current product doc (see the contradiction box) | Yes |
| High-value ("intelligent insights") | No | Yes — for example the **SensitivityLabel** of mail that was accessed; the training module lists `MailItemsAccessed`, `Send`, `SearchQueryInitiatedExchange`, `SearchQueryInitiatedSharePoint` here |
| Audit Search Graph API | Yes | Yes |
| Management Activity API bandwidth | Baseline (starts at 2,000 requests/min) | About twice Standard |
| Portal export limit | **50,000** rows | **1,000,000** rows |

Three retention footnotes. Standard logs made before **17 October 2023** were kept 90 days; since then, 180. Premium's one-year default only covers activity by users with an E5-level licence; non-E5 users and guests stay at 180 days. Records made by **non-user** entities (service principals, system events) are kept a fixed **one year**, whatever policy you set.

**2. Make sure there is something to search.** Auditing is on by default. Check in **Exchange Online PowerShell**: `Get-AdminAuditLogConfig | Format-List UnifiedAuditLogIngestionEnabled` should return `True`. (Run in Security & Compliance PowerShell, the same property always says `False` — a trap.) Turn on/off with `Set-AdminAuditLogConfig -UnifiedAuditLogIngestionEnabled $true`. Records appear **60–90 minutes** after the event for core services. **Nothing is back-filled**: records exist only from the day auditing (or a user's Premium auditing) was switched on.

> **Contradiction 1 — which tier logs MailItemsAccessed.** The training module (units 2, 3, 6) calls `MailItemsAccessed`, `Send`, `SearchQueryInitiatedExchange` and `SearchQueryInitiatedSharePoint` **Audit (Premium)** events. The current product doc *Use MailItemsAccessed to investigate compromised accounts* says `MailItemsAccessed` is ==@part of Audit (Standard)== and on by default for **Office 365 / Microsoft 365 E3 and E5** users. The product doc wins (Microsoft widened this logging to Standard in 2023; the overview now lists only the **SensitivityLabel** property of `MailItemsAccessed` as a Premium extra). On an exam question, read the wording: "high-value / intelligent-insights events" points to Premium; "is MailItemsAccessed available to an E3 user" is now **yes**.
>
> **Contradiction 2 — per-user switch.** The training unit says the **Microsoft 365 Advanced Auditing** service plan must be ticked **per user** (Microsoft 365 admin center > Users > Active users > user > Licenses and apps) before Premium events log — propagation 15–30 minutes, full logging up to 24 hours. The Purview service description says Audit (Premium) is enabled at tenant level by default for licensed users. In practice: if Premium events are missing for an E5 user, check that service plan.

**3. Who can search.** The **Audit Logs** or **View-Only Audit Logs** role. In the Purview portal these sit in the **Audit Manager** (search, export, change settings) and **Audit Reader** (search and export only) role groups. Creating audit retention policies needs **Organization Configuration**. **Administrative units** scope searchers: an *unrestricted* admin sees everything including non-user and system records; a *restricted* admin sees only users in their admin units.

**4. Running a search (portal).** Fields: **Date and time range (UTC)** (default last 7 days, maximum **180 days** per search), **Keyword Search**, **Admin Units**, **Activities – friendly names**, **Activities – operations names** (exact, comma-separated, for example `MailItemsAccessed,Send`), **Record types**, **Search name**, **Users**, **File, folder, or site**, **Workloads**. Searches run as background **jobs**:

- up to **10** jobs at once per user, only **one unfiltered**;
- broad jobs can take up to **48 hours**;
- completed jobs are kept **30 days** (re-open, re-export, **Copy this search**);
- above **100,000** results the dashboard shows an approximate count.

Results show Date (UTC), IP address, User, Record type, Activity, Item, Admin units, Details. The rich detail sits in the **AuditData** JSON column — parse it in Excel **Power Query** (Transform > JSON).

**5. Searching with PowerShell.** `Search-UnifiedAuditLog` in Exchange Online PowerShell. Dates are **UTC**. It returns **100** rows by default and **5,000** per call at most; page larger sets with `-SessionId` and `-SessionCommand ReturnLargeSet`. `Search-MailboxAuditLog` is being deprecated in its favour. For bulk programmatic download, Microsoft points to the **Office 365 Management Activity API** instead of scripts.

**6. MailItemsAccessed — the "which mail did they read" event.** Logged when mail is accessed by any protocol (POP, IMAP, MAPI, EWS, Exchange ActiveSync, REST). Two access types:

| `MailAccessType` | Meaning | Investigation meaning |
|---|---|---|
| **Sync** | Desktop Outlook (Windows or Mac) downloaded a folder — one record per folder, not per item | If the attacker's context synced, assume **every item in that folder** is compromised |
| **Bind** | A single message was opened; binds within **2 minutes** are rolled into one record (`OperationCount`) | Exactly which messages, by `InternetMessageId` |

Separate attacker from user by **ClientIPAddress**, **ClientInfoString**, **SessionId**. Duplicates within **one hour** are filtered unless context properties differ. The training unit adds that logging is **throttled** if a mailbox exceeds **1,000 bind events in 24 hours** (`IsThrottled` = True) and throttled binds never back-fill (the current product article no longer mentions throttling). Fill the gap with Exchange message trace, Entra sign-in logs, or the un-throttled `SearchQueryInitiated*` events.

**7. Copilot and AI activity.** Record types `CopilotInteraction` (Microsoft 365 Copilot, Security Copilot…), `ConnectedAIAppInteraction` (Copilot Studio agents, Entra-registered AI apps — needs DSPM onboarding) and `AIAppInteraction` (third-party AI sites via the Purview browser extension + DLP; **pay-as-you-go**, kept 180 days). Copilot auditing is part of **Audit (Standard)** — no extra setup. The record holds **metadata**: who, which app (`AppIdentity`), `AccessedResources` (with `SensitivityLabelId`), and in `Messages` only prompt/response **message IDs** plus a `JailbreakDetected` flag — not the prompt text. Admin changes show as `UpdateTenantSettings`, `CreatePlugin`, `DeletePlugin`, `EnablePromptBook`.

**8. Retention policies (Premium).** Purview portal > **Audit** > **Create audit retention policy**. Scope by **users**, **record type**, **activities**; pick a **duration** (7 days, 30 days, 6, 9 months, 1, 3, 5, 7 years, 10 years). The **3, 5, 7 and 10-year** options need the **10-Year Audit Log Retention add-on** on top of E5; 7 and 30 days need an E5 subscription. Pick one record type and an **Activities** list appears; pick several and the policy covers all their activities. Set a **priority** from **1** (highest) to **10000** (lowest). Custom policies always beat the default policy — even if shorter. Maximum **50** policies. The default policy is not shown and cannot be edited. Nothing is retroactive: a new duration applies to records written after the change. Deleting a policy can take **30 minutes** to take effect. PowerShell (Security & Compliance): `New-UnifiedAuditLogRetentionPolicy`.

## Where it lives

| Task | Portal / tool | Path or command |
|---|---|---|
| Search | Microsoft Purview portal | **Solutions** > **Audit** > **Search** (`purview.microsoft.com`; no Audit card → **View all solutions** > **Core** > **Audit**) |
| Same search | Microsoft Defender portal | **Audit** (`security.microsoft.com/auditlogsearch`) — identical tool |
| Retention policies | Purview portal | **Audit** > **Policies** / **Create audit retention policy** |
| Roles | Purview portal | **Settings** > **Roles and scopes** > **Role groups** (Audit Manager, Audit Reader) |
| Premium per-user plan | Microsoft 365 admin center | **Users** > **Active users** > user > **Licenses and apps** > **Microsoft 365 Advanced Auditing** |
| Check auditing on | Exchange Online PowerShell | `Get-AdminAuditLogConfig` |

```powershell
Connect-ExchangeOnline
# Every MailItemsAccessed record for two users over two weeks (UTC)
$log = Search-UnifiedAuditLog -StartDate 2026-01-06 -EndDate 2026-01-20 -UserIds user1,user2 -Operations MailItemsAccessed -ResultSize 1000
$log | Where {$_.AuditData -like '*"MailAccessType","Value":"Bind"*'} | FL
$log | Where {$_.AuditData -like '*"IsThrottled","Value":"True"*'} | FL
# Export SharePoint sharing for a month
Search-UnifiedAuditLog -StartDate 06/01/2025 -EndDate 06/30/2025 -RecordType SharePointSharingOperation |
  Select-Object CreationDate, UserIds, RecordType, AuditData | Export-Csv C:\AuditLogs\SharePointAudit.csv -NoTypeInformation -Encoding UTF8
```

## Exam traps

- ==!Audit (Standard) keeps 90 days.== ==+180 days== (90 only for logs before 17 October 2023).
- **Which emails did the attacker open?** ==+MailItemsAccessed==, Bind records, by `InternetMessageId`. ==!It is not FolderBind or MessageBind.== Tier: the training module says Premium; the current product doc says Standard for E3/E5 users (see Contradiction 1). A Premium-only answer about "intelligent insights" is the sensitivity label of the mail read.
- ==!Turning on auditing (or Premium for a user) shows last month's activity.== ==+Nothing back-fills==; records start at enablement. The same goes for a new retention policy.
- ==!Priority 10000 wins.== ==+Priority 1 is highest.== Custom policies beat the default, even when shorter.
- ==!E5 alone lets you keep logs 3, 5 or 7 years.== ==+Anything above 1 year needs the 10-Year Audit Log Retention add-on.==
- ==!Non-user (service principal, system) records can be kept 10 years with a policy.== ==+Fixed at 1 year==; policies don't apply.
- ==!Audit raises alerts in real time.== It is a search tool for past activity. Alerting belongs to Defender, Sentinel and Purview alert policies.
- ==!Search-UnifiedAuditLog runs in Azure PowerShell / Microsoft Graph PowerShell.== ==+Exchange Online PowerShell.==
- ==!Global Administrator automatically sees audit search.== The documented need is the **Audit Logs** / **View-Only Audit Logs** role (Global Admins get it because they are auto-added to the Exchange Online **Organization Management** role group, but the exam names the role).
- **Sync** = folder downloaded, assume all of it is exposed. **Bind** = one message opened.
- Portal search range is **180 days max per job**; time is **UTC**.
- `UnifiedAuditLogIngestionEnabled` shows `False` in Security & Compliance PowerShell even when auditing is on — check in **Exchange Online** PowerShell.
