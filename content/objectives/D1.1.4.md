## Azure first

- **Defender for Endpoint (MDE)** is the security agent on laptops and servers; its tenant settings live in the Defender portal under **Settings > Endpoints**. That page has sections: General, Permissions, **Rules**, Configuration management, Device management.
- An **indicator of compromise (IoC)** is a fingerprint of something bad: a **file hash** (a unique checksum of a file), an **IP address**, a **URL or domain**, or a **certificate** that signed a program. An indicator in MDE is *your* entry saying what to do when that fingerprint shows up.
- **Network protection** is the Windows component that blocks connections outside Microsoft Edge. **SmartScreen** does the blocking inside Edge.
- **AIR** (automated investigation and remediation) is MDE's robot analyst. Two Rules pages tune what it uploads and what it ignores.
- **Licence:** MDE is a Microsoft 365 product, so this is a portal tour for an Azure-only learner (Defender for Servers on an Azure VM is the one live route).

New to these? Read the Foundations pages linked above.

## In one sentence

The **Rules** section of **Settings > Endpoints** holds the tenant's own allow/block and tuning lists for Defender for Endpoint: **Alert suppression**, **Indicators**, **Web content filtering**, **Automation uploads**, **Automation folder exclusions** and **Custom data collection** (its own lesson, D1.1.5).

## Why it exists

Microsoft's detections are a generic guard dog. Every organisation has its own quirks: a homemade tool that looks like malware, a website the board wants blocked, a threat feed from a partner. The Rules section is where you hand the dog *your* list — "always bark at this", "never bark at that", "this room is off limits".

## What actually matters

### Indicators — the big one

- **Four tabs:** **File hashes**, **IP addresses**, **URLs/domains**, **Certificates**. Each indicator has an **action**, an **expiration**, and a **scope** (all devices or chosen device groups).
- **Actions per type** (current product):

| IoC type | Actions |
|---|---|
| Files | Allow · Audit · Warn · Block execution · Block and remediate |
| IP addresses | Allow · Audit · Warn · Block execution |
| URLs / domains | Allow · Audit · Warn · Block execution |
| Certificates | Allow · Block and remediate |

- **Audit** = alert, no block. **Warn** = user sees a warning and can bypass. **Allow** = never blocked and ==@no alert== (by design).
- **Who enforces:** the **cloud detection engine**, the **automated investigation and remediation engine** (Allow makes it ignore a bad verdict; Block makes it treat the item as bad) and the **endpoint prevention engine** (Microsoft Defender Antivirus).
- **Prerequisite switches** (Advanced features, D1.1.3): **Allow or block file** for file indicators; **Custom network indicators** for IP/URL/domain. File and cert indicators need Defender Antivirus with **cloud-based protection**. IP/URL needs **network protection in block mode**.
- **Limits worth memorising:** ==@15,000 indicators per tenant== (no increase). CSV import: ==@500 per batch==. IPs: **single addresses only — no CIDR, no ranges**, external only. A domain also matches all its subdomains. **HTTPS URL paths only match in Edge**; HTTP paths match in any browser. Certificates: **.CER or .PEM**, leaf certificates only; ==!Microsoft-signed certificates and apps cannot be blocked==.
- **Latency:** file blocks are typically enforced within **15 minutes**, average **30 minutes**, but can take upwards of **2 hours**. IP/URL: most blocks under **2 hours**, but up to ==@48 hours==. Certificate create/remove: up to **3 hours**.

**When indicators conflict** (testable — files and network indicators use different orders):

| Type | Who wins |
|---|---|
| IP / URL / domain, same target, different actions | ==@Allow > Warn > Block== |
| Two URL indicators on overlapping paths | the **longer path** |
| Two file-hash indicators for the same file | the **more secure (longer) hash** — SHA-256 beats SHA-1/MD5 |
| All-devices indicator vs a device-group indicator | the **device-group** indicator, for devices in that group |
| Certificate Block vs file-hash Allow on a file it signed | ==!certificate Block wins== — the combination is unsupported |
| MDE indicator Allow vs Defender Antivirus Block | ==+Allow== — MDE indicator policy beats antivirus policy |

For files and certs the full pipeline is: WDAC/AppLocker block → antivirus **exclusion** allow → file IoC Block/Warn → SmartScreen block → file IoC Allow → ASR / controlled folder access / antivirus block → allow. That is why an antivirus exclusion beats a file Block indicator.

- **Gotchas:** indicators are ==!not supported when Defender Antivirus is in passive mode==. File/cert indicators ==!do not override antivirus exclusions==. **Allow indicators win over web content filtering** blocks.
- **Contextual indicators:** from a file's page, **Add indicator** creates a file-hash indicator on the spot.

### Web content filtering

- Blocks **website categories**. Five parent groups: **Adult content**, **High bandwidth**, **Legal liability**, **Leisure**, **Uncategorized** (only *newly registered domains* and *parked domains*). ==!Don't block Uncategorized== — unexpected results.
- Wizard: **Add policy** > **General** (name) > **Blocked categories** > **Scope** (device groups, default **Select all**) > **Summary** > **Submit**.
- A policy with **no categories** = **audit-only** — watch first, block later. Unblocked categories are audited. **Block mode wins over audit mode** when policies overlap.
- Enforcement: **SmartScreen** in Edge; **network protection** in Chrome, Firefox, Brave and Opera.
- Up to **2 hours** before a policy is enforced. Wrongly categorised domain → **Dispute category** in **Reports > Web protection**; meanwhile, an **Allow** URL indicator.
- Licences include **MDE Plan 1 or Plan 2** and **Microsoft 365 E3** and E5. Turning it on needs **Core security settings (manage)** in unified RBAC.

### Alert suppression

**Settings > Endpoints > Rules > Alert suppression** lists suppression rules: turn on, edit, delete, and optionally **release** alerts already suppressed. Rule details show **status, scope, action, number of matching alerts, created by** and date. The current home for building rules is **alert tuning** in Defender XDR settings — taught in D1.1.2.

### Automation uploads and automation folder exclusions

- **Automation uploads:** toggle **Content analysis** and list **File extension names** and **Attachment extension names** that AIR may send to the cloud for inspection. The `"` entry covers files with **no extension**. Microsoft keeps submitted files **six months**.
- **Automation folder exclusions:** **Folder** (required; includes subfolders; trailing wildcard allowed), **Extensions**, **File names**, **Description** (required). Apply to **all onboarded devices**. They affect **only AIR**. ==!Excluded files are still scanned by antivirus.== Live response collecting an excluded file fails with `File is excluded`.
- Both need **Security Administrator** (or the **Core security settings (manage)** / **Manage security settings in Security Center** permission).
- Caveat: from **1 September 2026**, MDE's AIR no longer runs as a separate investigation experience (D1.1.7). The pages still exist; expect them on the exam as they were written.

## Exam traps

- "Block a /24 range of attacker IPs with one indicator" → ==!not possible==; single IPs only.
- "Block an internal IP" → ==!not possible== with indicators.
- "Block Microsoft Teams with a certificate indicator" → ==!Microsoft-signed cannot be blocked==.
- "Marketing needs one social site while Social networking is blocked" → ==+Allow URL/domain indicator scoped to Marketing's device group==. ==!Not a second WCF policy.==
- "Measure web usage before blocking anything" → ==+WCF policy with no categories selected (audit-only)==.
- "Stop AIR acting on files in `D:\Builds`" → ==+Automation folder exclusion==. ==!Not an antivirus exclusion== (that stops *scanning*).
- "Allow indicator raised an alert" → ==!Allow never alerts==. **Audit** does.
- Indicator not working on a device running a third-party AV with Defender in passive mode → indicators ==!are not supported in passive mode==.

- **Skip:** the TCP three-way-handshake explanation of why `ConnectionSuccess` appears for a blocked site, the `EnableFileHashComputation` Group Policy, and the Defender for Cloud Apps sync override. Too deep for SC-200.
- **Skip:** every CSV column type in the import table. Know CSV import exists, 500 per batch, and the sample file is on the import pane.
- **Skip:** the antivirus-exclusion family (custom, contextual, ASR, CFA exclusions) from the exclusions overview — that is D1.1.6. Here you only need: indicators and automation folder exclusions are **not** antivirus exclusions.
