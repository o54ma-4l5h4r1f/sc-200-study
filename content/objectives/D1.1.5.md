## Azure first

- **Defender for Endpoint (MDE)** already records a lot from every device — processes, files, network connections — into **advanced hunting** tables such as `DeviceProcessEvents`. To save space it does **not** record every single event.
- A **Log Analytics workspace** is the database that **Microsoft Sentinel** (the SIEM) reads. Data stored there is billed per GB ingested.
- **KQL** (Kusto Query Language) is how you read those tables: `TableName | where …`.
- A **device tag** is a label on a device ("Finance", "DomainController"). A **dynamic tag** is applied automatically by a rule in **Asset Rule Management** and updates itself about every hour.
- **Licence:** needs **MDE Plan 2** plus a Sentinel workspace. The workspace side is possible on an Azure subscription; the MDE side is not without Microsoft 365 licences (Defender for Servers on an Azure VM is the one possible route). Treat the screenshots as the lab.

New to these? Read the Foundations pages linked above.

## In one sentence

**Custom data collection** lets you write rules in **Settings > Endpoints > Rules > Custom Data Collection** that make chosen devices record **extra** endpoint events — beyond MDE's default telemetry — and send them to your **Microsoft Sentinel workspace** in five `DeviceCustom*` tables.

## Why it exists

MDE's default recording is like a CCTV system that saves a sample of frames to keep storage small. Usually that is enough. During a hunt, a compliance audit or an active incident you sometimes need **every** frame from **one** camera — every PowerShell script on the admin workstations, every file touched in the payroll folder.

Custom data collection is that "record everything here" switch, aimed at a narrow set of devices and events so the bill and the noise stay small. Microsoft made it **generally available in May 2026** — this bullet has **no training unit**, so this page is built from product docs only.

## What actually matters

- **It adds, it never replaces.** Custom rules run **alongside** MDE's default telemetry. They do not change or reduce it.
- **Five tables, and only five:**

| Table | Captures |
|---|---|
| `DeviceCustomProcessEvents` | process creation, termination, other process activity |
| `DeviceCustomImageLoadEvents` | DLL / image loads |
| `DeviceCustomFileEvents` | file create, modify, delete, access |
| `DeviceCustomNetworkEvents` | network connections (IPs, ports, protocols) |
| `DeviceCustomScriptEvents` | script execution (PowerShell, JavaScript…) |

- **A rule = table + action(s) + conditions.** Pick one table, pick which actions to collect, then add conditions on that table's columns to filter (folder path, process name, remote port…). Collected rows carry `RuleName` and `RuleLastModificationTime`, so you can tell which rule produced them.
- **Destination = a Microsoft Sentinel workspace.** You must **select the workspace** on the Custom Data Collection page, even if one is already connected. Only ==@one Sentinel workspace per tenant== can be used for custom data collection today. Ingestion is **billed by Sentinel**; the feature itself is included in MDE Plan 2.
- **Targeting = dynamic tags only.** Scope a rule to **all applicable devices** or to devices with **dynamic tags** from **Settings > Microsoft Defender XDR > Asset Rule Management**. The tag rule must have **run at least once**. ==!Manual (static) tags are not supported.== Dynamic tags refresh about **every hour**.
- **Limits and timing:**
  - ==@75,000 events per rule, per device, per 24-hour rolling window==. When hit, **that rule** stops on **that device** until the window resets; other rules keep going. (It was 25,000 before GA.)
  - Deployment to devices: typically **20 minutes to 1 hour**. Edits take the same. Disabling stops collection at the next agent check-in.
  - **Delete is permanent**; data already in Sentinel stays.
- **Supported devices:** **Windows 10 and 11** (minimum client version **10.8805**; Windows 10 needs ESU enrolment) and **Windows Server 2019 and later**. No macOS or Linux.
- **Good practice from Microsoft:** pilot on **5–10 devices**, watch volume for **24–48 hours**, prefer several narrow rules over one broad one. An **EDR exclusion** on a path or process can stop collection.

## Where it lives

| Step | Where |
|---|---|
| Create dynamic tag | **Defender portal > Settings > Microsoft Defender XDR > Asset Rule Management > Create a new rule** (conditions on device name, domain, OS platform, internet-facing, onboarding status, manual tags → apply a tag) |
| Connect the workspace | **Settings > Endpoints > Rules > Custom Data Collection** → select the Sentinel workspace name (top right) → **Workspace scope** |
| Create the rule | same page → **Create rule** → **General Information** → **Create rule** (table, actions, conditions) → **Define rule scope** → **Review and finish** → **Submit** |
| Edit / disable / delete | select the rule → **Edit** / **Enable** checkbox / **Delete** |
| Query the data | **Advanced hunting** or **Sentinel** logs, KQL |

Check that a rule is collecting from one device:

```kql
search in (DeviceCustomFileEvents, DeviceCustomScriptEvents, DeviceCustomNetworkEvents, DeviceCustomProcessEvents, DeviceCustomImageLoadEvents) "your_device_id"
| where DeviceId == "your_device_id"
| summarize EventCount = count() by RuleName, RuleLastModificationTime, $table
| order by RuleLastModificationTime desc
```

For testing only, Microsoft's "collect everything" trick is an always-true condition, e.g. `RemotePort not equals 0` (network), `FileName not equals ""` (file), `ProcessCommandLine not equals ""` (process) — on a tiny pilot group.

## Exam traps

- "Collect all PowerShell from admin workstations into Sentinel without changing the default MDE config" → ==+custom data collection rule on DeviceCustomScriptEvents, scoped by a dynamic tag==.
- "Target the rule with a tag I typed on 10 devices by hand" → ==!manual tags are not supported==. Build a dynamic tag in **Asset Rule Management**.
- "Send the custom events to the Log Analytics workspace of my choice, two workspaces" → ==!only one Sentinel workspace per tenant==.
- "Install the Azure Monitor Agent and write a DCR" → ==!wrong tool== for MDE endpoint telemetry. AMA + DCRs collect Windows event logs / Syslog / CEF (D1.3.2, D1.3.4).
- "Create a custom log table first" → ==!not needed==. The `DeviceCustom*` tables are fixed; custom tables are D1.3.7.
- Events stopped on one busy server mid-afternoon → ==+75,000-per-rule-per-device daily cap hit==; narrow the conditions.
- "Works on my Ubuntu servers" → ==!Windows 10/11 and Windows Server 2019+ only==.
- Custom data collection replaces default telemetry → ==!false==, it adds to it.
