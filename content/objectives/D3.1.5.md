## Azure first

- **A graph** here means **nodes** (things: a user, a laptop, a VM, a key vault) joined by **edges** (relationships: *can authenticate as*, *has permissions to*, *member of*). Not a chart.
- **Lateral movement** is an attacker hopping from the first machine they own to the next, using credentials or permissions they find, until they reach something valuable.
- **Microsoft Security Exposure Management** is the Defender portal feature that maps your assets and marks **critical assets** (domain controllers, key vaults, admins). The hunting graph and blast radius read its map.
- **Microsoft Sentinel data lake** is Sentinel's tenant-wide long-term store; **Sentinel graph** is built on it (D3.1.6). Both graph features on this page need it.
- **Licence note:** these features need Defender workloads feeding Exposure Management. An Azure-subscription-only lab will not show them — this page is a portal tour.

New to these? Read the Foundations pages linked above.

## In one sentence

The **hunting graph** draws who-can-reach-what as an interactive map from prebuilt scenarios inside advanced hunting, and **blast radius** draws, inside an incident, every path an attacker could take from the compromised thing to your critical assets.

## Why it exists

Answering "can this user reach the domain admins?" in KQL means joining a table to itself once per hop. It is slow and easy to get wrong. A picture of paths answers it in seconds.

Think of a burglar inside one flat of an apartment block. **Blast radius** shows every corridor and spare key leading from that flat to the basement safe. The **hunting graph** is the same building map, opened *before* a burglary to ask "which flats have a key to the safe?"

## What actually matters

### 1. Two graph features, one engine

| | **Hunting graph** | **Blast radius analysis** |
|---|---|---|
| Lives in | **Advanced hunting** (a tab) | The **incident graph** (attack story) |
| When you use it | Proactively, or while scoping | During an incident |
| Start from | A **predefined scenario** + inputs | A **node** in the incident graph |
| Shows | Paths / relationships the scenario asks for | Possible paths from that node to **critical targets** |
| Built on | Sentinel data lake + graph, Exposure Management data | Same |

Blast radius **extends and replaces Attack path analysis** in the incident graph. Both are listed by Microsoft as experiences powered by **Microsoft Sentinel graph**. Their costs and the custom-graph billing are covered in D3.1.6.

### 2. Prerequisites — the current state (November 2026)

- **Microsoft Sentinel data lake** onboarded. Both feature pages say customers who onboarded to the data lake *"before September 23rd, 2026 are eligible."* With the data lake in place, both are **auto-provisioned** at Defender portal sign-in.
- **Exposure Management (read)** or higher, plus an **advanced hunting** role for the hunting graph.
- Paths are only as good as the workloads feeding Exposure Management and the **critical assets** you classified.
- Training still labels the hunting graph **(Preview)**; the product article has no preview banner.

### 3. Create a hunting graph — three steps

Open **Advanced hunting**, then the **hunting graph icon** or **Create new > Hunting graph**. A tab named **New graph** opens (the training unit calls it "New hunt"). Then **Search with Predefined scenarios**:

1. **Select a scenario** and enter its inputs. Filter the scenario list by MITRE tactic buttons.
2. **Apply filters**, such as **Show only the shortest paths**, and edit the pre-set **Advanced filters** (table below).
3. **Run scenario** to render.

| Advanced filter | Values (operator: equals) |
|---|---|
| Source node | is critical · is vulnerable · is exposed to the internet |
| Target node | has sensitive data · has risk score · is vulnerable |
| Edge type | has permissions to · can authenticate as · member of · routes traffic to · has credentials of · has role on · contains · … (19 in all) |
| Edge direction | incoming · outgoing · both |

Scenarios worth recognising by name (product article names — the training unit still uses older labels such as *Nodes in highest number of paths to SQL data stores* and *Entities that have access to a key vault*; the product UI wins):

| Scenario | Input | Answers |
|---|---|---|
| **Attack paths to critical asset** | target critical asset | How could someone reach this crown jewel? |
| **Entity relationship map** | any source entity | What is this thing directly connected to? |
| **Paths between two entities** | start + target | Is there a path from A to B? |
| **Access to key vaults** | key vault | Who / what can reach this vault? |
| **Users with access to sensitive data** | storage account | Who can read this data? |
| **Potential data exfiltration by device** | source device | Which storage can this device reach? |
| **Choke points to SQL data stores** | (none) | Which nodes sit on the most paths to SQL? |
| **Paths to domain admins**, **Paths to domain compromise (DCSync)** | (none) | Hidden routes to full AD takeover |
| **Kerberoast / AS-REP roast paths to critical assets** | (none) | Roastable accounts on a path to critical assets |
| **External users with cloud resource access** | (none) | Guests with privileged cloud permissions |

### 4. Reading the graph

- **Nodes** are icons by type (compute, identity, data, keys & secrets …). A **number** on an edge means several relationships.
- Indicators: **golden crown** = critical asset; **red bug** = vulnerable; **blue plus** = explore connected assets; product icon = **discovery source**.
- **Grouped nodes** show a count; **ungroup** splits them. Select a node or edge for a details panel. Bottom right: **Zoom**, **Layers**.

### 5. Blast radius in an incident

In the incident graph, select a node → **View blast radius**. (If none exists, the menu says **No blast radius found**.) A new view shows the **eight top-rated** attack paths. **View full blast radius list** opens every reachable target; pick one to see its path. **Hide blast radius** returns to the incident graph. In the newer **incident cases** experience (preview): **Cases > Incident > *case* > Overview > Attack graph**, select an entity, review blast radius.

Limitations (likely distractors): paths bounded at **five hops for cloud, five for on-premises, three for hybrid** (up to seven overall); **possible** paths only; **known attack vectors** only; **scoped to your RBAC**; data freshness lags and **island nodes** can appear.

### 6. The KQL route — build the graph yourself

The same relationship data sits in two advanced hunting tables (D3.1.1): `ExposureGraphNodes` and `ExposureGraphEdges`. `make-graph` loads them as a graph in memory; `graph-match` searches it for a path pattern.

```kql
// Defender — what kinds of things have an edge INTO a virtual machine?
ExposureGraphEdges
| make-graph SourceNodeId --> TargetNodeId with ExposureGraphNodes on NodeId
| graph-match (SourceNode)-[edges]->(TargetNode)
    where TargetNode.NodeLabel == "microsoft.compute/virtualmachines"
    project IncomingNodeLabels = SourceNode.NodeLabel
| summarize by IncomingNodeLabels
```

Read it: *build a graph from edges and nodes; find every one-hop pattern ending at a VM; list the distinct labels of what points at VMs.*

```kql
// Defender — internet-exposed VMs that are also vulnerable to remote code execution
ExposureGraphNodes
| where isnotnull(NodeProperties.rawData.exposedToInternet)
| where isnotnull(NodeProperties.rawData.vulnerableToRCE)
| where set_has_element(Categories, "virtual_machine")
| project NodeName, NodeLabel
```

```kql
// Defender — edge types in your tenant, most common first (good first look at the graph)
ExposureGraphEdges
| summarize Edges = count() by EdgeLabel
| sort by Edges desc
```

## Exam traps

- ==!"Blast radius shows the path the attacker took."== ==+It shows possible paths== from a node to critical targets, based on known attack vectors.
- ==!"Blast radius lives in advanced hunting."== ==+Blast radius is in the incident graph==; the **hunting graph** is in advanced hunting.
- ==!"Attack path analysis is the incident-page feature."== ==+Blast radius extends and replaces it.==
- **Prerequisites:** Sentinel **data lake** + **Exposure Management (read)**. No data lake → neither feature.
- **Hop limits:** 5 cloud, 5 on-prem, **3 hybrid**; first view shows **8** paths.
- **Paths you cannot see:** RBAC scoping hides out-of-scope nodes — a "no path" result can mean "not allowed to see it".
- **`make-graph` builds, `graph-match` searches.** Not the other way round.
