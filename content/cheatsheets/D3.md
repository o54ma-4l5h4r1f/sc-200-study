# D3 — Perform threat hunting

*Review this last. Print it: Ctrl/Cmd + P. Every fact here comes from the D3 objective pages — open the page if a line surprises you.*

## D3.1.1 — Which table answers which question

| Question | Table | Time column |
|---|---|---|
| What ran / connected / wrote / changed / signed in **on a device** | `DeviceProcessEvents` · `DeviceNetworkEvents` · `DeviceFileEvents` · `DeviceRegistryEvents` · `DeviceLogonEvents` · `DeviceImageLoadEvents` (DLLs) | `Timestamp` |
| AV, exploit protection, ASR, everything else on the device | `DeviceEvents` | `Timestamp` |
| What is this device / installed / vulnerable | `DeviceInfo`, `DeviceNetworkInfo`, `DeviceFileCertificateInfo` · `DeviceTvm*` (posture, not attacks) | `Timestamp` |
| Who got which mail / attachment / link | `EmailEvents` → `EmailAttachmentInfo`, `EmailUrlInfo` (key ==@`NetworkMessageId`==) | `Timestamp` |
| What happened **after** delivery (ZAP, moves) | `EmailPostDeliveryEvents` | `Timestamp` |
| Who **clicked** a link | ==+`UrlClickEvents`== | `Timestamp` |
| Teams messages | `MessageEvents`, `MessagePostDeliveryEvents`, `MessageUrlInfo` | `Timestamp` |
| AD authentication seen by Defender for Identity | ==+`IdentityLogonEvents`== (not `DeviceLogonEvents`) | `Timestamp` |
| LDAP / DNS queries against DCs · directory changes · who an account is | `IdentityQueryEvents` · `IdentityDirectoryEvents` · `IdentityInfo`, `IdentityAccountInfo` | `Timestamp` |
| Entra sign-ins in advanced hunting | ==@`EntraIdSignInEvents`== / `EntraIdSpnSignInEvents` (replace `AADSignInEventsBeta` / `AADSpnSignInEventsBeta`; need **Entra ID P2**) | `Timestamp` |
| Activity inside Office 365 / SaaS (inbox rules, sharing, admin) | `CloudAppEvents` (Defender for Cloud Apps) — ==!not the same as `OfficeActivity`== | `Timestamp` |
| Alert title / severity · entities it touched | `AlertInfo` · `AlertEvidence` — join on ==@`AlertId`== | `Timestamp` |
| Behaviors (preview) | `BehaviorInfo`, `BehaviorEntities` | `Timestamp` |
| Assets and their relationships (attack paths) | `ExposureGraphNodes`, `ExposureGraphEdges` | — |
| Entra interactive sign-ins (Sentinel) | `SigninLogs` (`ResultType` "0" = success) | `TimeGenerated` |
| Entra directory changes · Azure control plane · Office 365 audit | `AuditLogs` · `AzureActivity` · `OfficeActivity` | `TimeGenerated` |
| Windows Security log · other Windows logs (Sysmon) | `SecurityEvent` · `Event` | `TimeGenerated` |
| Linux syslog · CEF appliances · Azure resource logs | `Syslog` (text in `SyslogMessage`) · `CommonSecurityLog` (pre-parsed) · `AzureDiagnostics` | `TimeGenerated` |
| Sentinel's own alerts / incidents · watchlists | `SecurityAlert` / `SecurityIncident` · `Watchlist` (`_GetWatchlist()`) | `TimeGenerated` |
| Threat intel | ==+`ThreatIntelIndicators` / `ThreatIntelObjects`== (legacy `ThreatIntelligenceIndicator` ==!no data after 31 Jul 2025==); value in `ObservableValue`, type in `ObservableKey` | `TimeGenerated` |
| Bookmarks · summary-rule run log | `HuntingBookmark` · `LASummaryLogs` | `TimeGenerated` |

- `*Events` = what happened (stream). `*Info` = what a thing is (snapshot, refreshed ==+every hour== per product docs; old training says 15 min). Keys: `DeviceId`, `NetworkMessageId`, `AlertId`.
- **`Timestamp`** = when the event happened (Defender tables). **`TimeGenerated`** = when the row was ingested (Sentinel tables). Streamed Defender tables carry **both**; a row >**48 h** late gets `TimeGenerated` overwritten with `now()` → ==+use `Timestamp` for the real event time==.

### Retention reach

| Data | Reached by | How far |
|---|---|---|
| Native Defender XDR tables | Advanced hunting | ==!**30 days**== |
| Sentinel tables (analytics tier) | Advanced hunting / Logs | The table's **analytics** retention (e.g. 90 d of a 2-year `SigninLogs` → AH sees 90 d) |
| Data lake tier only | ==+**Data lake exploration > KQL queries**==, KQL job, search job | Up to **12 years** |
| Beyond 30 d of Defender data | Stream the table to Sentinel with longer retention | Workspace retention |

Lake-only tables in AH: overview says ==!not available==; a known-issues note says new customers can. Safe exam rule: ==+long-term lake data → Data lake exploration or a search job==.

## D3.1.2 — KQL quick reference (beyond the basics)

### Matching text

| Operator | Matches | Case | Speed |
|---|---|---|---|
| `==` | whole value exactly | sensitive | fast |
| `=~` | whole value | insensitive | fast |
| `has` | a **whole term** | insensitive | ==+fast (term index)== |
| `contains` | anywhere, mid-word too | insensitive | ==!slow (scans)== |
| `in` / `in~` · `has_any` | one of a list · any term of a list | sens. / insens. | fast |
| `has_cs`, `!has`, `!contains`, `!=`, `!in` | case-sensitive / negated versions | — | — |

`"KustoExplorerQueryRun" has "Explorer"` = **false**; `contains` = **true**. Terms ≤ **3** characters aren't indexed. Table and column names are case-sensitive.

### All join kinds — ==!default is `innerunique`==

| `kind=` | Output |
|---|---|
| *(none)* / `innerunique` | Left **de-duplicated** on the key, then one row per match |
| `inner` | ==+Every== left–right matching pair |
| `leftouter` | All left rows; nulls where no right match |
| `rightouter` | All right rows; nulls where no left match |
| `fullouter` | All rows from both sides |
| `leftsemi` | Left rows that **have** a match — left columns only |
| `rightsemi` | Right rows that have a match — right columns only |
| `leftanti` (alias `leftantisemi`) | Left rows with ==@no== match — "what's new / missing" |
| `rightanti` (alias `rightantisemi`) | Right rows with no match |

Different key names: `on $left.Account == $right.TargetAccount`. Hygiene: smaller table left, time filter both sides, project before joining.

### Operators the exam reads

| Operator | One line |
|---|---|
| `summarize … by` | One row per `by` key. Unnamed `count()` → `count_` |
| `arg_max(TimeGenerated, *)` / `arg_min` | The **whole latest row** per group — not just the max time |
| `count()`, `countif()`, `dcount()` (estimate), `minif()`/`maxif()` | Correlate inside one table without a join |
| `make_set()` / `make_list()` | ==+Distinct== array / ==!all values, duplicates kept== |
| `take_any()` | Any one example value |
| `union withsource=T` | Stack tables; `T` names the source (`Type` column too). Wildcards OK |
| `search` | Every column of every table — ==!slowest==; scope with `search in (…)` |
| `between (a .. b)` | Range, works on times |
| `project-away` / `-keep` / `-rename` / `-reorder` | Drop / keep / rename / reorder columns |
| `order by` = `sort by` | Same operator, default **descending** |
| `distinct A, B` | Same as `summarize by A, B` |
| `let x = …;` · `datatable` · `dynamic([…])` | Name a value or sub-query · inline table · inline list |
| ==@`materialize()`== | Run a `let` sub-query **once**, cache it (≤ **5 GB** per node). Pays only if used ≥2 times |
| Function | Saved query called like a table; **Save > Save as function**; can take parameters (ASIM parsers) |
| ==@`parse`== | Fixed-shape text; modes `simple` (default), `regex`, `relaxed`; failures → ==!null, not error==. ==+Prefer to `extract`== |
| `extract(regex, group, text)` | Regex; group `0` = whole match; null if none |
| `parse_json()` / `Col.key` | Read `dynamic` (JSON) columns |
| ==@`mv-expand`== | One row per array element — ==!multiplies rows== (other columns copied) |
| `mv-apply` · `externaldata` | Sub-query per element · read a CSV from a URL |
| ==@`make-series … default=0 on T from … to … step 1h`== | One array per group with **every** bucket filled (`bin()` leaves gaps) |
| `series_decompose_anomalies(s, 1.5)` | Default threshold **1.5**; higher = fewer flags |
| `render` | `timechart`, `barchart`, `columnchart`, `piechart`, `areachart`, `scatterchart` |
| `make-graph` / `graph-match` | ==+Builds== a graph / ==+searches== it (exposure tables) |

```kql
// Order matters: last event was a logon (1) vs. latest logon per account (2)
SecurityEvent | summarize arg_max(TimeGenerated, *) by Account | where EventID == 4624
SecurityEvent | where EventID == 4624 | summarize arg_max(TimeGenerated, *) by Account
// union then summarize = one total; summarize inside brackets = counts only that table
SecurityEvent | union (SigninLogs | summarize count())
```

| Hunting pattern | Shape |
|---|---|
| Brute force → success | `countif` fails + successes per account per `bin()`, both > 0 |
| Password spray | `dcount(UserPrincipalName) by IPAddress` over failures |
| First seen | `let` baseline, then `join kind=leftanti` |
| Rare = suspicious | `dcount(DeviceId) by FileName, SHA256`, keep ≤ 2 |
| IOC sweep | `let` list → `union` tables → `where … in (list)` |

Speed: time filter first · `has` over `contains` · specific column, not `search *` · case-sensitive when possible · parse, don't extract. Log Analytics with no time filter uses the picker (default **24 h**). **Queries** = Microsoft's samples; **Query explorer** = your saved ones. **New alert rule > Microsoft Sentinel alert** → analytics rule.

## D3.1.3 — Advanced hunting

| | Guided mode (**Create new > Query in builder**) | Advanced mode (**Create new > Query**) |
|---|---|---|
| KQL | No — dropdowns | Yes |
| Data | ==!Defender XDR only== | Defender XDR + Sentinel tables |
| Notes | Data domains; basic filters = **AND only**; **All filters** toggle for AND/OR + subgroups; EventType = `ActionType`; **Edit in KQL**; sample size default **10,000** | Several queries per tab — the one under the **cursor** runs; **Set in query**; all **UTC** |

### Quotas — know all four (+CPU)

| Limit | Value |
|---|---|
| Date range | **30 days** native Defender; Sentinel = analytics retention |
| Rows | ==@**100,000**== per query (10,000 = guided sample size) |
| Timeout | **10 minutes** |
| Result size | **64 MB** (partial results beyond) |
| CPU | Measured every **15 min**; warning > **10%**; ==!blocked at 100%== until next cycle |

Separate quotas for manual queries, custom detections and the API. **Query resources report** (button, or **Reports > General**): 30 days, Low/Medium/High; Security Reader+ sees everyone's.

### Do things with results

| Action | Fact |
|---|---|
| Save | **My queries** (you) · **Shared queries** (whole org) · **Community queries** = Microsoft GitHub, reviewed. **Share link** = URL |
| Export | Table → Excel, chart → JPEG (advanced); guided says CSV |
| ==@Link to incident== | New or existing incident; impacted assets + related evidence; ==+one alert per unique combination of impacted entities==. ==!No bookmarks in AH== — this replaces them |
| ==@Take actions== — device | Isolate, investigation package, AV scan, automated investigation, restrict app execution — needs `DeviceId` |
| Identity | **Disable user**, **reset user authentication** — needs SID (`AccountSid`) / `AccountObjectId` |
| File | Quarantine — needs `SHA1`/`SHA256` **plus** `DeviceId` |
| Email | Move to folder, soft/hard delete, submit, automated investigation — delete needs `EmailDirection` + `SenderFromAddress` |

All actions → **Action center > History**. MDE manual AIR stopped **1 Sep 2026** (run a full AV scan); MDO AIR unchanged. **Go hunt** / **Hunt for related events** writes a starter query from an entity.

## D3.1.5 — Hunting graph and blast radius

| | ==@Hunting graph== | ==@Blast radius== |
|---|---|---|
| Lives in | Advanced hunting (**Create new > Hunting graph**) | **Incident graph** → node → **View blast radius** (cases: **Overview > Attack graph**) |
| Starts from | **Predefined scenario** + inputs → filters → **Run scenario** | A node; first view = **8** top paths; **View full blast radius list** |
| Shows | Relationships the scenario asks | ==!Possible== paths to **critical targets** — not the path taken |

- Prerequisites: ==+Sentinel data lake== (onboarded before 23 Sep 2026 eligible; auto-provisioned) + ==+Exposure Management (read)== (+ an advanced hunting role for the hunting graph). Paths depend on classified **critical assets**.
- Blast radius ==+replaces Attack path analysis==. Hops: **5 cloud, 5 on-prem, 3 hybrid**; known vectors only; ==!RBAC-scoped== ("no path" can mean "can't see it").
- Badges: crown = critical, red bug = vulnerable, blue plus = explore. Scenarios: attack paths to critical asset, paths between two entities, access to key vaults, paths to domain admins / DCSync, Kerberoast / AS-REP roast…
- Cost: hunting graph and blast radius = ==+no graph charge==.

## D3.2.2 / D3.2.3 — KQL jobs vs summary rules vs search jobs vs restore

| | ==@KQL job== | ==@Summary rule== | ==@Search job== | Restore |
|---|---|---|---|---|
| Reads | Data lake (+ **federated**) | Analytics, Basic, Auxiliary, lake (==!no federated==) | **One** table | One table's old data |
| Joins | Many tables, full joins | Several (Basic: `lookup` ≤ **5** Analytics) | ==!None== | — |
| Schedule | One time or scheduled (By minute, Hourly, Daily, Weekly, Monthly) | Bin **20, 30, 60, 120, 180, 360, 720, 1440** min | On demand | On demand |
| Look-back | Up to **12 years** | ==!≤1 day== (one bin; ==!no history==) | 12 years, span ≤ **1 year** | min **2 days** |
| Timeout | **1 hour** | **10 min** | **24 h** | — |
| Max results | Depends on timeout | **500,000** records | **100 million** records | — |
| Limits | **5** concurrent/tenant (==!extra rejected, not queued==), **100** enabled, **1** output table | **100 active** per workspace | **10** concurrent, **200** runs/day, **200** result tables | **4**/table/week, 2 concurrent, 1 active per table |
| Destination | New `_KQL_CL` (Analytics) / `_KQL` (lake, System tables) / existing (same schema) | `_CL` table, ==@always Analytics== | `_SRCH` | `_RST` |
| Needs lake | ==!Yes== | No | No | — |
| Price | GB analyzed | Free on Analytics source; scan on Basic/Aux; + Analytics ingestion | GB analyzed | — |
| Where | Defender **Data lake exploration > Jobs** (no Azure portal) | **Sentinel > Configuration > Summary rules** (both portals) or workspace **Settings > Rules** | **Microsoft Sentinel > Search** | (D1.2.2) |

Rule of thumb: **frequent, recent, shrink it** → summary rule. **History, joins, lake** → KQL job. **One big table / pre-lake archive** → search job. Search-job numbers: product docs win over training (1M / 5 / 100 / 100).

- **KQL job rules:** name unique in tenant, ≤ **256** chars, ==!no `#` or `-`==; start ≥ ==@30 min== after creation; ==!editing a one-time job runs it now==; edit must keep the **same output schema**; can't delete a running job; disable doesn't stop a queued run. ==!No `adx()`, `arg()`, `externaldata()`, `ingestion_time()`, user functions==. ==!`TimeGenerated` overwritten if > 2 days old== → copy it. Lake latency ≤ **15 min** (use a delay). Templates: Hunting, Anomaly detection, Baseline. Jobs page lists KQL, Notebook, Graph jobs — ==!notebook/graph view-only==.
- **Summary rule rules:** ==!no time filter in the query== (bin supplies it); default wait 3.5 min up to 10% of bin; `binDelay` ≤ 1,440. ==!No `union *`, `isfuzzy=true`, `workspaces()`, `app()`, `resource()`, `ADX()`, `ARG()`, `bag_unpack`/`narrow`/`pivot`, user functions==. Target ≤ **0.01%** of source, record < **1 MB**. Retries **10 within 8 h**; **8** consecutive failures → on hold; **rerun failed bin**. Destination table deleted → suspended. ==!Delete irreversible.== No workspace transformation on the destination; public cloud only, ==!not via Lighthouse==. Run log = **Summary Logs** diagnostic setting → `LASummaryLogs` (costs extra). Templates: **Content hub** (type Summary rules) → **Templates** tab. Added columns `_RuleName`, `_BinSize`, `_BinStartTime`…; reserved names get `_Original` prefix.
