# D1 — Manage a security operations environment

*Review this last. Print it: Ctrl/Cmd + P. Every fact here comes from the D1 objective pages — open the page if a line surprises you.*

> **Portals.** Defender portal = `security.microsoft.com` (Defender XDR settings **and** Sentinel). Sentinel in the Azure portal is ==!unsupported after 31 March 2027== — expect Defender portal paths. Entra admin center = groups and Entra roles. Intune admin center = recommended home of ASR policy.

## D1.1 — Defender XDR settings and automation

### The four "automatic" things — never mix them up

| | ==@Automation rule== (Sentinel) | ==@Playbook== (Sentinel) | ==@AIR== (Defender) | ==@Automatic attack disruption== (Defender XDR) |
|---|---|---|---|---|
| What | No-code if/then on incidents/alerts | Logic Apps workflow (or Python *generated playbook*) | Robot analyst: verdict + remediation | Emergency brake on a high-confidence **incident** |
| Who writes logic | You (conditions + ordered actions) | You (Logic Apps designer) | Microsoft | Microsoft — ==!you can't add logic== |
| Started by | Incident created / updated, alert created (Scheduled/NRT) | Only an **automation rule**, or **manually** | Certain alerts | Correlated signals, detectors **≥99%** confidence |
| Switch? | Create on **Automation** page | Create on **Automation** page | MDE: ==!no switch== (on by default); levels per device group | ==!No switch== — meet prerequisites; opt-out = **support case** |
| Key limits | Alert trigger: ==@Run playbook== (+ preview Simple Flows **Update Alert**: status/classification/determination/owner, ==!not severity==); playbook step moves on after **2 min** | Incident playbook ↔ incident rule; alert ↔ alert; ==!entity = manual only== | Pending actions time out **7 days** = **rejected** | Acts on: contain device/IP/user, disable user, revoke session… |

- **2026 change:** from **1 September 2026** MDE AIR is no longer a separate experience and can't be triggered manually — ==+run a full AV scan== instead. ==+Email (Defender for Office 365) AIR is unchanged.== Automation levels and the Action center still exist.
- **Email AIR never auto-remediates.** Soft delete, block URL, turn off forwarding/delegation all wait in the **Action center**.
- **Expansion** to **10+ devices** waits for approval. **Undo** in Action center **History**: ==@Security Administrator or higher==. Filters up to **6 months**.

### MDE automation (remediation) levels — per device group

| Level | Behaviour |
|---|---|
| ==+Full - remediate threats automatically== | Recommended. Default for tenants created **on/after 16 Aug 2020** |
| Semi - require approval for **all folders** | Default for tenants created **before 16 Aug 2020** |
| Semi - … **core** folders (wizard: *system* folders) | Approval only for OS folders (`\windows\*`) |
| Semi - … **non-temp** folders | Auto only in temp/download folders |
| No automated response | No AIR — ==!and excluded from attack disruption== |

==+Any Semi level still lets attack disruption act without approval.== Same setting, three doors: device group wizard, **Endpoints > General > Auto remediation**, **Defender XDR > Automated response > Devices**.

### Attack disruption — prerequisites worth a mark

| Need | Detail |
|---|---|
| Contain device | MDE **device discovery = Standard discovery**; works on **unmanaged** devices too |
| Contain user | Sense agent **v10.8470+** |
| Disable user | AD → MDI sensor on a DC (action account default **LocalSystem**); ==+cloud-only → done in Entra without MDI== |
| MDO | Exchange Online; mailbox auditing: `MailItemsAccessed`, `UpdateInboxRules`, `MoveToDeletedItems`, `SoftDelete`, `HardDelete` |
| Defender AV state | ==+Any== — Active, Passive or EDR block mode |
| Exclusions | (Also listed on **Endpoints > Advanced features**.) **Settings > Microsoft Defender XDR > Automated response** > Identities (**Add user exclusion**) / Devices (device groups, **Exclude IP**, policy application by tag) |
| Seen where | **Attack Disruption** tag, yellow banner, graph labels, summary card, Activities (*Performed by: AttackDisruption*), Action center, `DisruptionAndResponseEvents` |

Contain ≠ isolate: **contain** = other devices refuse its traffic; **isolate** = cut an onboarded workstation off the network.

### Device groups

- Match on name, domain, tag, OS. Different properties = **AND**; rows of the same property = **OR** (up to 10). Up to **2,000** groups.
- ==@A device joins only the highest-ranked match (rank 1 = highest).== No match → **Ungrouped devices** (can't delete or re-rank).
- ==!A group with no Entra user groups is visible to everyone.==
- Turning on classic MDE roles: Security Reader ==!loses access== until assigned, and it's ==!irreversible==. New customers since **16 Feb 2025** get **unified RBAC** only. ==!Unified RBAC doesn't scope devices== — device groups still do.

### ASR rules (D1.1.6)

| Mode | Code | Event ID |
|---|---|---|
| Off | `0` | — |
| Block | `1` | **1121** |
| Audit (allows, logs) | `2` | **1122** |
| Not configured | `5` | — |
| Warn (Unblock 24 h) | `6` | **1129** = user overrode Warn |

- **5007** = settings changed. Log: *Windows Defender > Operational*. Hunting: `DeviceEvents`, `ActionType` starting `Asr`.
- Straight to Block (standard protection): **vulnerable signed drivers**, **LSASS credential stealing**, **WMI persistence**. Everything else Audit first.
- Warn: ==!not in Configuration Manager==; not on LSASS or Office code-injection rules; Windows 10 1809+.
- Needs Defender AV **active** + real-time protection; ==!Windows only==. Recommended tool: ==+Intune endpoint security==. ==+Group Policy beats MDM by default== (`MDMWinsOverGP` = 1 flips). PowerShell lowest. `Set-MpPreference` ==!overwrites==, `Add-MpPreference` appends.
- Per-rule exclusions: only GPO, Intune and Defender portal endpoint security policies. Security settings management: assign to ==+Entra device groups==, check-in **90 min**.

### Sentinel automation rules (D1.1.10) and playbooks (D1.1.11)

- Conditions: AND; **condition groups** = OR. Update trigger adds **Changed / Changed from / Changed to / Added** and ==@Updated by== (stop loops).
- Order: each trigger has its own queue; same order number = ==!random sequence, not parallel==. **Rule expiration** = pen-test noise closing.
- Defender portal: alert-trigger rules see ==!Sentinel alerts only==. After onboarding, **Incident provider** condition is gone.
- Playbook triggers: ==@Microsoft Sentinel incident / alert / entity==; Defender portal adds **Playbook with alert trigger / case trigger** (Defender SOC connector). Old *Alert automation (classic)* ==!deprecated March 2026==.
- **Consumption** = templates. **Standard** = ==!no templates==, must be **Stateful**, private networking.
- Templates = ARM template; after deploy ==+authorize each API connection==. Managed identity needs ==+Sentinel Responder== on the workspace to update incidents (Reader only receives).
- Run status: **Missing permissions** = *you* lack Playbook Operator; **Grant permission** = *Sentinel* lacks Automation Contributor.

## D1.2 — Sentinel platform

### Table tiers and retention

| | Analytics tier | Data lake tier | XDR default tier |
|---|---|---|---|
| For | Detection, hunting, all features | Compliance, forensics, high-volume low-value | Defender XDR hunting |
| Retention | Analytics **30 d – 2 years**; total up to **12 years** | **30 d – 12 years** | **30 days**, fixed |
| Analytics rules / hunting | ✓ | ==!✗== | hunting ✓ |
| Restore | ✓ | ✗ | — |

- ==+Exam numbers: 90 days included on a Sentinel workspace; 30 days Defender XDR; 2 years max hot; 12 years max total.==
- Extend XDR tables (e.g. `DeviceEvents`) by raising retention in **Sentinel > Configuration > Tables** → table created in the workspace. ==!Reset both to 30 → disables the XDR connector.==
- Shorten retention → deleted after **30-day** grace. Basic-plan table ==!can't be managed from Defender==.
- **Search job** → `_SRCH` (one table, 24 h timeout; product doc: **100 million** records, **10** concurrent, **200** result tables, **200** runs/day — ==!training's 1M / 5 / 100 / 100 is older; product wins==). **Restore** → `_RST` (min 2 days, 1 active per table, ==@4 restores per table per week==, 2 concurrent/workspace, ==!not Auxiliary==, delete when done).
- CLI `--total-retention-time` max **2,556 days**; 12 years (4,383) via portal/REST/PowerShell.

### Workbooks and SOC optimization

- Workbook templates come from the **Content hub**; **Save** makes your copy (an Azure resource storing JSON). Blank workbook → check **required data types**. Auto refresh 5 min–1 day, off by default. **Print/PDF = Azure portal only** (Defender: **Open in Azure**).
- SOC optimization: refresh **every 24 h**. **Data value** (billable tables, last **30 days**, unused by detections) and **Coverage** (threat-based; **High >75% / Medium 30–74% / Low 0–29%**). ==!Never suggests cutting UEBA or TI-matching tables.== ==+Standard Sentinel roles only.==
- Cost levers: **Split** transformation (match → Analytics, rest → lake-only ==@`_SPLT`== table) vs **Filter** (drops rows). Commitment tier from **100 GB/day**; raising ==!restarts the 31-day period==, lowering waits for it to end. **Table insights** (Data & connectors > Tables, preview) = volume/cost per table — ==!not billing-grade==.

### AMA / DCR numbers

| Item | Number |
|---|---|
| Event sets | **All** (Security + AppLocker, ==!not System==) · **Common** (audit trail incl. 4634) · **Minimal** (4624, 4625, 4688, 1102; ==!no 4634==) · **Custom** (XPath) |
| XPath | `LogName!XPathQuery`; **20 expressions/box, 100 boxes/rule**; XPath 1.0 — ==!no `contains` / `starts-with`== |
| AMA throughput | Windows ≈ **5,000 EPS**; Linux forwarder ≈ **10,000 EPS** |
| WEC | ≈ **3,000 EPS**; >50,000 lifetime sources → `wecutil` |
| Syslog/CEF ports | Appliance → forwarder **UDP/TCP 514**; daemon → AMA **TCP 28330** (AMA 1.28.11+) |
| Syslog level | Minimum level = that level **and worse**; exact levels need the API |
| Diagnostic settings | Max **5** per resource; **one** destination per type |
| Policy-managed connector | Needs **remediation task** for existing resources; grey after **14 days** no data |
| Logs Ingestion API | Monitoring Metrics Publisher on the DCR, up to **30 min** (403 before); **1 MB**/call; DCE only for private link / old DCRs; TLS 1.2+; column names ≤ **45** chars |

- Non-Azure machine → ==+Azure Arc before== enabling the connector. DCR can sit in any RG ==+in the same tenant==. Data can take **5 min**. ==!Re-editing a DCR in the portal wizard wipes JSON-only changes== (transformations) — keep editing JSON.
- WEF: AMA ==+only on the WEC==; source-initiated = GPO **SubscriptionManager**, ACL of **computer** accounts; Security log needs **NETWORK SERVICE** in **Event Log Readers**; ==!WEF doesn't enable auditing==; Kerberos-encrypted in a domain.
- CEF + Syslog on same facility → stored **twice**. Fix: separate facilities or a transformation. Forwarder = **Linux 64-bit**; the DCR installs AMA but ==+you still run the forwarder installation script== (514 listener) — ==!training says no script; docs win==.
- `_CL`: only the **portal** adds the suffix. Custom column on an Azure table = `_CF`. ==!Table schema change doesn't update the DCR.== Azure tables can't be deleted. HTTP Data Collector API ==!end of support 14 Sep 2026== (still accepts TLS 1.2+, unsupported) → Logs Ingestion API; classic-table **migrate** is ==!one-way==.
- TI page in Defender = ==@Intel explorer== (formerly *Intel management*). STIX = **format**, TAXII = **transport**. TIP (Graph `tiIndicators`) connector ==!stopped June 2026== → upload API (no connector, never shows Connected). Ingestion rules affect ==!connector data only==.

## D1.4 — Detections

### Analytics rule types

| Type | Logic by | Customise | Key limits |
|---|---|---|---|
| **Scheduled** | You (KQL) | Fully | Interval & lookback **5 min–14 days**, interval ≤ lookback; 5-min built-in delay; **150 alerts/run**; **512 enabled / 1,024 total** |
| **NRT** | You (KQL) | Mostly | Every **1 min**, 2-min delay; ==@50 enabled / 100 total==; **30 alerts/run**; ==!no schedule, no threshold== |
| **Microsoft security** | Source products | Filters only | ==!Not available in Defender portal / with XDR integration== |
| **Threat intelligence** | Microsoft | No | One rule (*Microsoft Defender Threat Intelligence Analytics*); no premium licence; same indicator in 24 h → one incident |
| **Fusion** (ML) | Microsoft | Source signals + exclusions only | One rule, on by default; ==!not in Defender portal== |
| **ML behavior analytics** | Microsoft | On/off | Anomalous SSH / RDP login; 30-day baseline |
| **Anomaly** | Microsoft ML | Via **one** duplicate | Writes `Anomalies` only — ==!no alerts, no incidents== |

Scheduled wizard: **10 entity mappings** × 3 identifiers, 500 entities/alert; suppression up to **24 h**; alert grouping default **5 h**, max **7 days**, 150 alerts/incident; custom details **20**/rule; Results simulation = 50 runs. ==!In the Defender portal leave *Create incidents* Enabled.== **Disable** keeps a rule; **Delete** has no undo. Rules querying ==!other subscriptions/tenants== run on the creator's credentials → auto-disabled if that access is lost.

- Query: return `Timestamp`/`TimeGenerated` + `ReportId` (+ `DeviceId`); after `summarize` use `arg_max`. ==!Don't filter on Timestamp.== Dynamic title: up to **3** `{{Column}}`s; custom details **20 pairs / 4 KB**.

- MITRE page: **preview**, ATT&CK v18, counts **active scheduled + NRT** rules with tags. **Simulated** = available but not enabled. Tactic = why, technique = how.
- Anomaly tuning: built-in can't be edited → **Duplicate** (one copy, starts **Disabled**, Flighting) → promote to Production → original ==+flips to Flighting==. Too many anomalies → ==+raise the threshold==. UEBA anomalies = on/off only.

## Traps → truth

- ==!Alert-trigger automation rule can change severity== → ==+Run playbook (plus preview Simple Flows Update Alert — status/classification/determination/owner, never severity)==.

- ==!Responder can run playbooks== → ==+add Playbook Operator==.
- ==!Automation rule can call an entity playbook== → ==+entity playbooks are manual only==.
- ==!Enable attack disruption in Settings== → ==+built in; meet prerequisites; opt-out by support case==.
- ==!Semi automation blocks disruption== → ==+only No automated response excludes a group==.
- ==!Full automation auto-remediates email== → ==+email actions always wait for approval==.
- ==!Pending action eventually runs== → ==+times out after 7 days as rejected==.
- ==!Device in two groups belongs to both== → ==+highest rank only==.
- ==!Indicator for a /24== → ==+single external IPs only==.
- ==!Automation folder exclusion stops AV scanning== → ==+AIR only==.
- ==!ASR Audit blocks== → ==+Audit logs 1122 and allows; Block logs 1121==.
- ==!Intune always beats GPO== → ==+GPO wins unless MDMWinsOverGP = 1==.
- ==!WEF events land in SecurityEvent== → ==+`WindowsEvent`==.
- ==!Minimal includes logoff== → ==+Common has 4634; Minimal doesn't==.
- ==!Install AMA on the firewall== → ==+Linux 64-bit forwarder on 514==.
- ==!Policy covers existing resources== → ==+create a remediation task==.
- ==!Query `ThreatIntelligenceIndicator`== → ==+`ThreatIntelIndicators` / `ThreatIntelObjects`==.
- ==!API adds `_CL`== → ==+only the portal does==.
- ==!7 years in Analytics tier== → ==+Analytics max 2 years; Data lake for 12==.
- ==!Data lake table still fires detections== → ==+Analytics tier needed==.
- ==!Sentinel analytics rules correlate by default in Defender== → ==+off; use `#INC_CORR#` at the start==.
- ==!New custom detection only sees new data== → ==+first run covers 30 days==.
- ==!Hourly custom detection looks back 1 h== → ==+4 h==.
- ==!Scheduled lookback 30 days== → ==+5 min–14 days==.
- ==!Microsoft security / Fusion rules in the Defender portal== → ==+not available; Defender XDR correlation does it==.
- ==!Anomaly rules create incidents== → ==+`Anomalies` table only; tune a duplicate==.
- ==!Simulated MITRE coverage = protected== → ==+available but not enabled==.
