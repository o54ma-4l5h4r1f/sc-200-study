# D2 — Respond to security incidents

*Review this last. Print it: Ctrl/Cmd + P. Every fact here comes from the D2 objective pages — open the page if a line surprises you.*

> **Portals.** Defender portal `security.microsoft.com` = incidents, alerts, cases, devices, identities, email, cloud apps, Copilot. Purview `purview.microsoft.com` = DLP/IRM alerts, IRM cases, Audit, eDiscovery. Entra admin center = ID Protection, Conditional Access, diagnostic settings. Azure portal = Defender for Cloud pages (alerts, suppression, workflow automation) and Sentinel's investigation graph and bookmarks.

## D2.1 — Respond to alerts and incidents

### Alert vs incident vs case

| Thing | What it is | Key facts |
|---|---|---|
| **Alert** | One detection | Must always belong to an incident/case; **Move alert** if correlated wrongly (comment required) |
| **Incident** | Correlated alerts + entities + evidence | Defender merges on shared entities/artifacts/time/sequence. Source → target, source closed as `Redirected`; ==!Microsoft picks the direction==. Manual merge up to **5**. Sentinel incident max **150** alerts ("150+" link) |
| **Incident case** (preview, ==+recommended==) | Defender **Cases > Incident**, wraps one incident | **Priority score**: >**85** top, **15–85** medium, <**15** low. ==!Closing a case leaves alerts' status alone== (legacy page: Resolved resolves all active alerts) |
| **Generic case** | Hand-made work item (TI lead, follow-up) | Links incidents, indicators (preview), recommendations; has **Priority**, not severity |
| **IRM case** | Purview, one **user** | Different product — ==!don't confuse with Defender cases== |

- **Won't merge** if: one Closed, different assignees, different classification/determination, entity limit, different device groups (if on). ==!Resolved cases can't be merged.== Merge needs a comment + reason.
- **Recommended correlations** shows related incidents on the graph ==!without merging==.
- Case templates (**Cases > Case management settings**): custom fields, custom statuses (under **New / Open / Closed**), **SLA** timers (Active, At Risk, Breached, Paused, Completed). SLA ==!single-tenant only== in preview. Email on SLA change = automation rule, **Case updated** trigger.
- Case history **180 days**; audit syncs to ==@`SecurityCaseEvent`== automatically (==!can't turn off==) when a primary Sentinel workspace is connected.
- Tasks: Sentinel (Azure) tasks sync ==!one way== into Defender; Defender ==!can't auto-create tasks== yet.

### Closing classification — two vocabularies

| Azure portal (Sentinel) | Defender portal | Sync translation |
|---|---|---|
| True Positive – suspicious activity | True positive + determination | TP → TP – suspicious activity |
| ==@Benign Positive== – suspicious but expected | ==@Informational, expected activity== | ↔ |
| False Positive – incorrect alert logic / – **incorrect data** | False positive | FP → FP – incorrect data |
| Undetermined | — | Not set → Undetermined |

Pen test = **benign** (B-TP), not false. FP = it didn't happen. Defender **Active** shows as Sentinel **New**. Comment limits: **30,000** chars, **100** per incident. Bookmarks ==!created only in the Azure portal==. Escalate = change ==+Owner==, not severity.

### MDO email response (D2.1.1)

- **Real-time detections** (P1) = malicious mail at delivery. **Explorer** (P2) adds All email, Campaigns, URL clicks, saved queries, post-delivery events. Both **30 days** back, default yesterday + today. Export **200,000** rows.
- Select **≤100** → every action; **101–200,000** → only **Move or delete** or **Propose remediation**. ==!Dropped / on-prem / hard-deleted mail is not remediable.==
- **AIR (email)**: actions ==!wait for approval== — only URL/file **similarity clusters** auto-approve. Pending times out after **one week** (*Terminated By System*). No threat → closes itself.
- **ZAP**: last **48 h**, on by default (malware, phish, high-confidence phish), also Teams chats.
- **Submissions**: mail up to **30 days** old. Block entry default **30 days**; Allow = **45 days after last use** (Submissions page) vs ==!1 day== (Explorer Take action).
- Original vs **latest** delivery location: latest shows ZAP/admin moves, ==!not user moves==.

### Purview DLP / IRM extras (D2.1.2)

- DLP lifecycle: Trigger → Notify → Triage → Investigate → Remediate → Tune. Purview has ==!no classification field== (Resolved + comment). ==!Resolving doesn't stop repeats== — fix the policy.
- Retention: Defender DLP incidents **6 months**; Purview dashboard **30 days**.
- IRM statuses: **Needs review** → **Confirmed** (to a case) / **Dismissed**; Needs review deleted after **120 d**. Active cases limit **2,000** (training said 100). Usernames **pseudonymized** by default.
- IRM role groups: **Admins** = policies only (==!no alerts==); **Analysts** = alerts/cases, ==!no content explorer/forensics==; **Investigators** = alerts + content; **Insider Risk Management** = all.
- Defender ↔ IRM sync (~30 min): New/In progress = Needs review; Resolved + TP = Confirmed; Resolved + FP or Informational = ==@Dismissed==.
- Sentinel: use the ==+Purview IRM data connector== (synced incidents carry no alert content).

### Defender for Cloud extras (D2.1.3)

- Alerts need a ==+paid Defender plan==; free tier = posture only. Alerts kept **90 days** (even if resource deleted). Severity High/Medium/Low/Informational.
- **Suppression rule**: alert ==!still generated==, auto-set Dismissed. Only for types that ==!fired at least once==. Subscription (portal/REST) or **management group via Azure Policy**. Expiry Custom or None (training: "up to six months" — product wins).
- **Workflow automation** = consumption Logic App; triggers: alert, recommendation, regulatory compliance. Run existing app = Logic App Operator; create = Logic App Contributor.
- DNS alerts = ==@Defender for Servers Plan 2== (standalone Defender for DNS gone). Network-layer alerts need a **public IP**.
- MDE alerts on cloud resources ==!don't sync status== between portals. Use the **Tenant-based** Defender for Cloud connector in Sentinel.

### MDCA extras (D2.1.4)

- Classify **TP** (suspend, compromised, reset) · **B-TP** (dismiss, exclude/tag IP) · **FP** (dismiss, tune).
- Anomaly learning period **7 days**; sensitivity **High** = System suppressions only (==!higher = fewer suppressions==). Legacy policies (Ransomware activity, Suspicious inbox forwarding…) ==!disabled since June 2025== → dynamic threat detection model.
- ==!Unsanctioned ≠ blocked==: block needs MDE integration, a supported gateway, or a block script. Risk score **1–10** (90+ factors, 31,000+ apps).
- Suspend user ==!reverts if on-prem AD sync overrides it==. M365 OAuth **Ban** ==!doesn't revoke existing permissions==.
- Real-time download block on unmanaged devices = ==+session policy== (Conditional Access App Control).

### ID Protection extras (D2.1.5)

| Verdict | Action |
|---|---|
| True positive | ==+Confirm compromised== (user risk → High) → reset / block |
| False positive | ==+Confirm safe== (learning mode) |
| Benign TP (pen test, known VPN) | ==+Dismiss== — ==!password unchanged== |

- **Sign-in risk** → MFA (**Medium and High**, authentication strength MFA). **User risk** → **High**, **Require risk remediation**. Both: sign-in frequency **Every time**. ==!Never both risks in one policy.== Not MFA-registered → ==!blocked==. Precedence: Block > Require risk remediation > Require password change.
- **Leaked credentials** = user risk, always High; ==!MFA doesn't fix it==. Token-theft detections ==!no longer auto-remediated by MFA==. Very-high-confidence blocks → error **50053**.
- ==!Can't dismiss risk for deleted users== (support case). Workload identities: ==!managed identities out of scope==; full detail needs **Workload Identities Premium**.

### MDI extras (D2.1.6, D2.1.9)

- Sensor on **DCs, AD FS, AD CS, Entra Connect**; v3.x = Server 2019+, v2.x = 2016 or earlier. ==!Only DC sensors run remediation==, using the DC's **local system account** (required for v3.x).
- Classic alert categories: Reconnaissance and discovery · Persistence and privilege escalation · Credential access · Lateral movement · Other. Defender-format alerts use MITRE-style categories; **Detection source** tells which.
- Lateral movement walkthrough: **SMB recon** → **overpass-the-hash** → **pass-the-ticket** → **remote code execution on DC**. These are ==@MDI== alerts, not MDE.
- LMP (lateral movement path) = **exposure** (what could happen) on **Attack paths** tab; pass-the-ticket = **alert** (what happened).
- Quiet benign alerts: **Excluded entities** (classic) or **alert tuning** (Defender format). Old name: ==@Azure ATP==.

### Attack story and blast radius (D2.1.9)

- Attack story = **alert story** + **incident graph** (play, entity pane actions, **Go hunt**: All Activity / Related Alerts / All User anomalies — UEBA, 30 d).
- **Blast radius** = ==+possible next paths== to critical assets (not where it has been). **8** top paths; hops **7** total — **5** cloud, **5** on-prem, **3** hybrid. Needs ==@Sentinel data lake== + ==@Exposure management (read)==. Replaces Attack path analysis.
- Only the ==+primary== Sentinel workspace correlates with Defender alerts.

### UEBA (D2.1.7)

`InvestigationPriority` (**0–10**, one event, `BehaviorAnalytics`) vs `AnomalyScore` (**0–1**, pattern, `Anomalies`). Peers: `UserPeerAnalytics` top **20**. Useful after ~**one week**. Turn on: Entra Security Admin + Sentinel Contributor + Log Analytics Contributor (RG). ==!No licence fee, but storage costs.==

### Copilot and agents at a glance (D2.1.8)

| Embedded skill | Where |
|---|---|
| Incident summary (auto; ≤**100** alerts; cached ≤1 week, ==+redisplay free==) | Incident > Copilot / **Summarize** |
| Guided response: **triage, containment, investigation, remediation** | **Recommendations** |
| Script analysis | ==!Attack story / device timeline event > Analyze== (not advanced hunting) |
| File analysis, device/identity/email summary, incident report | File > Analyze; entity pages; **Report** |
| Query assistant (English → KQL) | Advanced hunting |

| Agent | Portal | Key fact |
|---|---|---|
| **Phishing Triage Agent** | Defender | User-reported phish. ==+Resolves FPs, leaves TPs open==. Tags incident **Agent**. Needs MDO **P2**, alert policy *Email reported by user as malware or phish* on, ==!Auto-Resolve tuning off== |
| Security Alert Triage Agent (preview) | Defender | Same agent, extended to identity and cloud alerts |
| Threat Intelligence Briefing Agent | Defender / standalone | Briefing every **7 days** by default |
| Threat Hunting Assistant | Advanced hunting | Writes, runs, interprets KQL |
| Security Analyst Agent | Defender / standalone | Runs as *you* |
| ==@Dynamic Threat Detection Agent== (preview) | Defender | ==+Always on, no setup==; alerts with **Detection source = Security Copilot** |
| Identity Risk Management Agent (preview) | Entra (Risky users > Start agent) | ==!Suggests only==; needs Entra ID P2 |
| DLP / IRM Alert Triage agents | Purview | Needs attention / Less urgent / Not categorized; ==!active policies only== |

- Agents ==!aren't on automatically==: deploy from **Security Copilot > Security Store**. Identity = **Entra Agent ID** (recommended) or a user.
- **SCUs**: Provisioned (min **1**, billed per hour, ==!no rollover==) · Overage · **E5/E7 inclusion** = **400 SCUs/month per 1,000 licences**, max **10,000**, resets monthly; ==!Sentinel-only customers not eligible==.
- Embedded vs standalone: embedded pane **recommends**, you act; standalone `securitycopilot.microsoft.com` = sessions, promptbooks, plugins (put "**Defender**" in the prompt). Defender Chat keeps last **10** conversations.

### Device response actions (D2.2.2)

| Action | Key facts |
|---|---|
| ==@Isolate device== | Keeps the ==+MDE service connection== (live response still works). Selective: **Outlook + Teams**. ==+Auto-lifted after 7 days==. Offline retry **3 days**. Force-release script expires in **3 days**. Proxy → use selective. macOS/Linux: no exclusions |
| **Restrict app execution** | Code integrity: ==+only Microsoft-signed files run==. Needs Defender AV |
| ==@Contain device== | For **unmanaged** devices: ==+every other onboarded device blocks it==. ≤**100** at once, ~**5 min** |
| **Contain user** | ==!Automatic only== (attack disruption); blocks network logons/RPC/SMB/RDP; ==!doesn't disable the account==; lifts within **5 days**; undo = **Global Administrator** |
| **Run AV scan** | Quick/Full; works in ==+passive mode==; CPU `ScanAvgCPULoadFactor` **50%** |
| **Collect investigation package** | Zip: ==@Autoruns== (persistence), Network connections, Prefetch, Processes, Scheduled tasks, Security event log, Services, SMB sessions… Fails on low battery / metered |
| Restricted mode (high-value assets) | Set ==!at onboarding only==; blocks chosen action groups incl. live response |

Plan 1 only: AV scan, isolate, stop and quarantine file, file indicator. **Live response + investigation package = Plan 2.** Since **1 Sep 2026** MDE AIR is gone as a separate/manual experience → ==+run a full AV scan==.

### Live response

- **Prerequisites**: enable **Live Response** in Advanced features (needs *Manage portal system settings*); **Live Response for Servers** separate; **unsigned script execution** optional (PowerShell only). Device group needs an **automation remediation level**. Scripts ==!must be in the library first==.

| Basic (read) | Advanced (change) |
|---|---|
| `cd`, `dir`, `processes`, `services`, `drivers`, `connections`, `registry`, `persistence`, `scheduledtasks`, `startupfolders`, `fileinfo`, `findfile`, ==@`getfile`== | `run`, `putfile`, `library`, `remediate`, `undo`, `analyze`; macOS/Linux `collect`, `scan`, `isolate`, `release` |

| Limit (product docs win) | Value | Training said |
|---|---|---|
| Concurrent sessions / tenant | **50** | 10 |
| Sessions per user / device | **5** / 1 | 1 / 1 |
| Inactive timeout | **30 min** | 5 min |
| Command timeout | 10 min (30 for `getfile`, `findfile`, `run`) | — |
| `getfile` / `fileinfo` / library upload / `putfile` | 3 GB / **30 GB** / 250 MB / 300 MB Win (10 MB other) | fileinfo 10 GB |

Ctrl+C cancels ==!in the portal only==. **Command log** records every command.

|---|---|

### Attack disruption (D2.2.4)

| Action | Executed by |
|---|---|
| Contain device / Contain IP / Isolate device (preview, workstations) / Contain user | Defender for Endpoint |
| ==@Disable user== (AD via DC sensor; synced → both; cloud-only via *Microsoft Defender for Identity* enterprise app) | Defender for Identity |
| Revoke session / Suspend user in Entra | Entra ID |
| OAuth app compromise | Defender for Cloud Apps |
| AWS deny / Okta suspend (preview) | Sentinel connectors |

- Spot it: **Attack Disruption** tag, **yellow banner**, graph labels, summary card, Activities filter *Performed by: AttackDisruption*. Policy status **Active / Inactive (released) / Not applicable / No status**.
- Hunt the **blocks**: `DeviceEvents` ActionType containing `ContainedUser` / `ContainedDevice`; `DisruptionAndResponseEvents` = ==!outcomes only== (ReportType Prevented / Blocked / PolicyUpdated) — the Contain/Disable action itself is in the **Action center**.
- **Undo**: device → **Release from containment/isolation**; user → **Enable user** or Action center > History > **Undo**; IP → Action center > Undo. ==+Investigate and clean first.==
- Exclusions: **Settings > Microsoft Defender XDR > Automated response** (Identities, Device groups, IPs, Policy application → **Skipped**). Opt-out = **support case**. ==!Semi still allows disruption; only No automated response excludes.==

## D2.3 — Investigate with Purview and Graph

### Purview Audit (D2.3.1)

| | Audit (Standard) | Audit (Premium) |
|---|---|---|
| Default retention | ==@180 days== (90 before 17 Oct 2023) | 180 d; ==@1 year== for Entra, Exchange, SharePoint, OneDrive (E5 users only) |
| Retention policies | No | Up to **1 year**; **10 years** with the ==@10-Year Audit Log Retention add-on== (3/5/7/10 y all need it) |
| `MailItemsAccessed` | ==+Yes for E3/E5 users== (product doc; training says Premium) | Yes, plus **SensitivityLabel** of mail read (intelligent insights) |
| Export | **50,000** rows | **1,000,000** rows |
| Management Activity API | Baseline (2,000 req/min) | ~2× |

- Check: `Get-AdminAuditLogConfig` in ==+Exchange Online PowerShell== (S&C PowerShell ==!always says False==). Records in **60–90 min**. ==!Nothing back-fills.==
- Search: max **180 days** per job, **UTC**, ≤**10** jobs per user (one unfiltered), up to **48 h**, jobs kept **30 d**. `Search-UnifiedAuditLog`: 100 rows default, **5,000** max per call.
- `MailItemsAccessed`: **Sync** = folder downloaded → assume all exposed; **Bind** = one message (2-min aggregation). Throttle at **1,000 binds/24 h** (training).
- Policies: priority **1 = highest**, 10000 lowest; ==!custom beats default even if shorter==; max **50**; non-user records fixed **1 year**.
- Copilot: `CopilotInteraction` in Standard; holds ==!message IDs, not prompt text==.
- Roles: **Audit Logs** / **View-Only Audit Logs** (Audit Manager / Audit Reader groups); retention policies = **Organization Configuration**.

### eDiscovery content search (D2.3.2)

- Classic Content search / eDiscovery Standard / Premium ==!retired 31 Aug 2025== → one **eDiscovery**; content search = system case named ***Content Search***. Statistics replace collections; **Process manager**.
- Query = ==@KeyQL== (not KQL): `property:value` (no space), operators **UPPERCASE**, space = OR, ==!prefix wildcard only==, ==!empty query = everything==, case-insensitive, UTC.
- Export: PST/MSG; ==!packages deleted after 14 days==. Premium adds **review sets**.

| Search and purge | Value |
|---|---|
| Connect | `Connect-IPPSSession -EnableSearchOnlySession` |
| Do it | `New-ComplianceSearch` → `Start-ComplianceSearch` → `New-ComplianceSearchAction -Purge -PurgeType SoftDelete` / `HardDelete` |
| Role | ==@Search And Purge== (Purview **Organization Management**); ==!eDiscovery Manager alone can't purge== |
| Limits | ==!10 items per mailbox per run== (100 via Graph, premium); **50,000** mailboxes; ==!Exchange only== — no SharePoint/OneDrive, Teams or unindexed |
| Better if you have MDO P2 | Use MDO email remediation |

### Graph activity logs (D2.3.3)

| Item | Value |
|---|---|
| Records | ==+Every HTTP request== to Graph (who, IP, URI, method, status) |
| Licence | ==@Entra ID P1 or P2== (==!not Free==) |
| Least role | ==@Security Administrator== |
| Turn on | Entra > Monitoring & health > **Diagnostic settings** > `MicrosoftGraphActivityLogs` → workspace / storage / Event Hubs; or Sentinel **Entra ID** connector. ==!Off by default; no filtering== (use transformation / Basic plan) |
| Latency | ~**30 min**, up to **2 h**; new setting up to **3 days** |
| Volume | ~**15 GiB/month per 1,000 users** |
| Tables | `MicrosoftGraphActivityLogs` (Log Analytics/Sentinel) vs `GraphAPIAuditEvents` (Defender AH; status code is a **string**) |
| Hunting | `401/403` denied, `429` throttled; join `SignInActivityId` ↔ `UniqueTokenIdentifier` |

Audit = specific audited activities. eDiscovery = **content**. Graph logs = **every API call**. Sign-in logs = token issued, ==!not what was read==.
